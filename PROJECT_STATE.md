## กฎ Google Flow ที่ล็อกแล้ว

ลำดับต่อหนึ่งช็อตคือ:

```text
เปิดโปรเจกต์ของช็อต → อัปโหลดครั้งเดียว → รอการ์ดรูปเดิมในหน้าเดิม
→ เมนูการ์ดรูป → ทำให้เคลื่อนไหวครั้งเดียว → พิสูจน์ thumbnail ใน Composer → ใส่ Prompt
→ กดปุ่มแม่ Generate ครั้งเดียว → อนุมัติครั้งเดียว
→ รอคิว/เรนเดอร์โดยไม่แตะหน้า → ดาวน์โหลดผลใหม่ของช็อตนั้น
```

- หนึ่ง state transition ทำ physical action ได้หนึ่งครั้ง
- หลังมี submission receipt, คิว, Stop หรือเปอร์เซ็นต์ ห้ามส่ง Prompt/แนบรูป/เปิดโปรเจกต์ใหม่
- ทุกคำสั่งต้องผูก Job + Shot + Run + Lease + Client + owner tab
- Passive observer อ่านหลักฐานได้ แต่ห้าม Reload, Submit หรือกด UI
- Gemini/ChatGPT ใช้รูปใน user turn เดิมได้ ห้ามบังคับแนบ Preview ใหม่
- Product, Story และ Drama ใช้กฎเดียวกันเมื่อพบ Policy: เฉพาะ terminal `failure_code=FLOW_POLICY_BLOCKED` ที่ Extension ยืนยันจากการ์ดปัจจุบันว่ามีข้อความ Policy + ไม่หักเครดิต + Retry ครบ และมี fingerprint ใหม่เท่านั้น จึงใช้รูป canonical เดิมสร้าง local motion ของ output slot/ฉากนั้นทันทีตั้งแต่ครั้งแรก แล้วเดิน source/scene ถัดไป
- หลังรับ terminal ดังกล่าว ห้าม Retry ด้วย safe Prompt, ห้ามอัปโหลด/ส่งรูปเดิมซ้ำ และห้ามย้ายโควตาไปสร้าง Alternate Take จากรูปอื่น; Checkpoint เดิมต้องทำให้ event ซ้ำเป็น idempotent
- Final ห้ามรับคลิป SHA ซ้ำและห้ามปลอม local motion เป็นคลิป Flow งานผสม Product ใช้ `google_flow_hybrid_composite`; Story/Drama ใช้ `google_flow_story_hybrid_fallback` โดยยังเก็บ content-mix ของ Drama แยก และทุกโหมดต้องนับ Flow จริงกับ local motion แยกกัน
- ข้อความเข้าคิว/กำลังสร้าง/ระบบไม่ว่าง/ข้อผิดพลาดชั่วคราวไม่ใช่ความล้มเหลว และการ์ด Policy เก่าห้ามกระตุ้น fallback; ต้องรอหรือกู้ใน Run เดิม และรับ structured code/fingerprint จาก Extension รุ่นตรงกันเท่านั้น
