# SmartFlow AI — แผน UX/UI และความเสถียรทั้งระบบ

วันที่ 5 กันยายน 2026 • อ้างอิง Source ปัจจุบัน ไม่ใช่หน้าจอ Tk รุ่นเก่า

## เป้าหมาย

ให้ผู้ใช้รู้ 3 อย่างในทุกหน้า: กำลังทำงานอะไร ต้องทำอะไรต่อ และผลงานถูกเก็บที่ไหน เปิดใช้งานผ่าน `SmartFlow AI.exe` เหมือนเดิม โปรแกรมกับ Extension ใช้สถานะงานและ Checkpoint ชุดเดียวกัน

## สิ่งที่ลงมือในรอบนี้

- CTA ยอมรับคำถามที่ชวนผู้ชมตอบและเติมเฉพาะส่วนที่ขาด หลีกเลี่ยงนำชื่ออังกฤษที่ไม่มีคำอ่านกลับเข้าเสียง
- กู้ได้เฉพาะ suffix ที่โปรแกรมเดิมเติมจริงก่อนมี paid Voice checkpoint; เก็บภาพและบทที่ AI เขียนไว้ ไม่เปลี่ยนบทของเสียงที่จ่ายแล้ว
- ส่ง pronunciation_notes ผ่าน analysis checkpoint → manifest → Voice → Subtitle และรองรับชื่อ Hunter x Hunter แบบเดียวกัน
- Preview service แยกงานเบา: FFmpeg ทีละงาน เก็บเพียงค่าล่าสุดที่รอ ใช้ cache เมื่อข้อความ/สไตล์/ฟอนต์เหมือนเดิม เก็บ preview ก่อนหน้าขณะรอ และผูก media กับ process/token จริง
- หน้า Subtitle ตรวจผลเฉพาะ preview ทุก 180 ms จนเสร็จ ไม่เรียก Full State จากการปรับสไตล์ คำขอ Full Poll ที่ชนกันเข้าคิวต่อ
- ตัวเลือกสไตล์ภาพ 8 แบบ: ตามเรื่อง, เสมือนจริง, ภาพยนตร์, อนิเมะ 2D, แอนิเมชัน 3D, สีน้ำ/นิทาน, คอมิก, กำหนดเอง พร้อมแนวภาพเพิ่มเติมไม่เกิน 400 ตัวอักษร
- สไตล์ติดกับ Job/Batch/Series และถูกใส่ในทุกคำสั่งสร้างภาพ รวม bounded retry ของ Extension; งานเก่าใช้ `auto` ตามพฤติกรรมเดิม รูปที่ทำเสร็จแล้วไม่ถูกสร้างใหม่เพราะเปิดใช้ฟีเจอร์นี้
- ChatGPT แสดงข้อความใช้โมเดลปัจจุบันแทนช่องเลือกที่ถูกปิดใช้งาน Gemini ยังเลือกโมเดลได้
- ปรับฟอร์ม Story ให้หัวข้อกับเนื้อเรื่องชิดกัน ไม่ยืดแถวแรกจนเกิดพื้นที่ว่างมากเมื่อแผงขวาสูง
- ข้อความ Extension แยกชัดว่า “ส่งบทและภาพครบแล้ว” และ Desktop ยังต้องทำเสียง/วิดีโอ
- เพิ่มการทดสอบพฤติกรรม latest-wins, cache, media token, CTA repair, คำอ่าน, การส่งสไตล์ และตรวจ Hybrid ทุกหน้าจาก runtime ที่เปิดผ่าน EXE

## แผนหน้าจอทั้งหมด

### ลงมือเพิ่มแล้ว — Desktop phase 2

- Dashboard มีแผงงานปัจจุบัน/งานที่ทำต่อได้อยู่ก่อน Hero และสถิติ ไม่แสดง READY หรือ Safe Mode เปิดอยู่แบบตายตัวเมื่อสถานะจริงไม่ตรง
- Story และ Drama มีหน้าตรวจ Storyboard: ภาพ+บท+พรอมต์+คลิปแต่ละฉาก แยก Flow จริง/ภาพเคลื่อนไหวในเครื่อง และแถบสถานะ 5 ขั้นจาก Checkpoint จริง
- เพิ่มคำอ่านเฉพาะงานและพรีวิวข้อความ Voice แบบไม่ใช้เครดิต ใช้ร่วมกับ Subtitle; ป้องกันการแก้ทับ paid Voice และการบันทึกด้วย revision เก่า
- ตรวจคำที่ควรแก้ตั้งแต่บันทึก Analysis ก่อนขั้นสร้างภาพ ไม่ต้องรอให้ภาพครบถึงรู้ว่าบทมีคำอังกฤษ
- Log ค้นตาม Job/ข้อความ/บริการ/ข้อผิดพลาด คัดลอกเฉพาะผลกรอง และอ่านผ่าน compact logs แทน full Library snapshot
- ปรับ Dialog responsive และการคืน focus; แอนิเมชันใหม่รองรับ reduced motion/หยุดเมื่อซ่อนหน้าต่าง

ขอบเขตที่ยังไม่ได้ทำใน phase 2: ปุ่มสร้างภาพเฉพาะฉากใหม่, พจนานุกรมร่วมทุกช่อง, Style collections แบบรวมเสียง/ซับ/โลโก้, Timeline เวลาแต่ละขั้นย้อนหลัง และ Output QA แบบภาพดำ/เสียงเงียบ ทั้งหมดเป็นขั้นถัดไป ไม่แสดงว่าเสร็จแล้วและไม่เสี่ยงสร้างคำขอเสียเครดิตซ้ำเพื่อให้มีปุ่มครบ

## แนวตกแต่งและการเข้าถึง

- คงพื้น navy และแสง cyan/purple ของแบรนด์ ใช้พื้นหลังเคลื่อนไหวเบาใน Dashboard ลดในหน้าเครื่องมือ และพักเมื่อหน้าต่างซ่อนหรือระบบลดการเคลื่อนไหว
- ใช้ระยะห่าง 8/12/16/24/32 px; ข้อความเนื้อหาประมาณ 14–16 px คำช่วยไม่ควรต่ำกว่า 11–12 px
- แต่ละส่วนมีปุ่มหลักหนึ่งปุ่ม สีแดงใช้กับการลบ/หยุดที่มีผลจริง ไม่ใส่หลายปุ่มใหญ่แข่งกัน
- Loading ของคำสั่งเริ่มทันที แต่เปอร์เซ็นต์ต้องมาจากงานที่เสร็จจริง มีคำอธิบายเมื่อรอเว็บไซต์ ห้ามเพิ่มเปอร์เซ็นต์ปลอมตามเวลา
- Animation ทางเข้าประมาณ 160–240 ms เน้น opacity/transform; พื้นหลังต้องไม่รับ pointer events; เคารพ reduced motion และ keyboard focus
- Modal ต้องปิดด้วย Escape/ปุ่มปิด คืน focus ให้ปุ่มต้นทาง และไม่ซ้อนหลายชั้นโดยไม่จำเป็น

## แผนความเสถียรของโปรแกรมและ Extension

ลำดับสำคัญ: ความถูกต้องของผลงาน → กู้ต่อได้ → ความเร็ว → การตกแต่ง

1. รักษา transaction ที่เคยผ่านจริง: upload ครั้งเดียว → Animate → พิสูจน์ attachment → submit ครั้งเดียว → approve ครั้งเดียว → รอผลของ shot เดิม → download → validate → checkpoint → next shot
2. แยกสถานะ Desktop กับ Extension: AI images complete / voice ready / Flow clips complete / final ready อย่าใช้คำว่า complete ของบริการหนึ่งตัดสินทั้งงาน
3. ตรวจ readiness ของเสียงตั้งแต่บันทึกบท ก่อนภาพหลายฉากจบ; unknown proper nouns ให้แก้ในแผงคำอ่านพร้อม Preview โดยไม่สุ่มคำอ่านเอง
4. ให้ retry ตรงขั้นที่ขาด ใช้ paid request ID เดิม ห้ามเรียก AI Voice ใหม่เพราะ poll หลุด และห้ามสร้างภาพใหม่ถ้า checkpoint ครบ
5. Policy fallback ต้องมี structured current-card evidence + no-charge + Retry ตามสัญญาเดิม ใช้รูป canonical ทำ local motion ทันทีและรายงานจำนวนแยก; queue/busy ไม่ใช่ policy
6. ค่อยแยก UI engine, state snapshots และ worker orchestration ออกจาก `ui/main_window.py` หลังมี behavior tests ของแต่ละส่วน ห้ามย้าย monolith ทั้งไฟล์ในครั้งเดียว
7. แยก snapshot ตามหน้า/ส่วนและใช้ revision เพื่อไม่โหลดทุก Job ทุกครั้ง; กล่อง preview เป็นส่วนแรกที่ทำแล้ว หน้า Library/Log ควรตามมา
8. ทุกรุ่นออก Candidate ก่อน ระบุ automated/installed-web/Final QA แยกกัน และซิงก์ source-folder-ZIP-Bridge ให้ตรง

## ไอเดียเพิ่มเติมที่ยังไม่ลงมือ

- Storyboard review: แสดงภาพ+บททำแล้วใน phase 2; เหลือ “สร้างฉากนี้ใหม่” โดยเก็บฉากและเครดิตเดิม
- Style collections: บันทึกชุดสไตล์ภาพ+เสียง+ซับ+โลโก้ของช่อง และเลือกก่อนเริ่มงาน โดยไม่เปลี่ยน Job เก่า
- Pronunciation dictionary: คำอ่านรายงานและพรีวิวข้อความทำแล้วใน phase 2; เหลือคำอ่านเฉพาะช่องพร้อมตัวอย่างเสียง
- Job timeline: แสดงเวลาเริ่ม/จบของแต่ละขั้นและสาเหตุรอ เห็นทันทีว่าช้าที่เว็บหรือเครื่อง
- Output QA: ตรวจไฟล์อ่านได้ เสียงมีจริง ความยาวถูก ภาพไม่ดำ และไม่มี SHA ซ้ำก่อนประกาศ Final
- Scene policy summary: สรุปฉากใดใช้ Flow จริง/ภาพเคลื่อนไหว และกดดูต้นทางได้
