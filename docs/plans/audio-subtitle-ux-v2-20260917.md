## เป้าหมายหน้าจอ

สองการ์ด radio หลัก กดได้ทั้งใบ มีขอบ/ไอคอน/ข้อความบอกว่าเลือกแล้ว ไม่ใช้สีอย่างเดียว:

1. **เสียงต้นฉบับจากคลิป** — ใช้เสียงพูดและบรรยากาศที่ติดมากับวิดีโอ ไม่เรียกสร้างเสียงพากย์ API.
2. **เสียงพากย์ API SmartSub** — สร้างเสียงจากบทที่บันทึกไว้ เลือกเสียงจากการตั้งค่า SmartSub เดิม.

ใช้ค่าเดิมของงานหรือผู้ใช้ ไม่เปลี่ยน default เงียบ ๆ. เก็บ **ไม่ใช้เสียงหลัก** ในส่วนเพิ่มเติมพร้อมแสดงในสรุปเมื่อเลือก ไม่ลบความสามารถเก่า.

แยกเป็น3ส่วน:
- เสียงหลัก: การ์ด2ใบและตัวเลือกตามโหมด ระดับเสียงต้นคลิป/เสียงพากย์แยกกันเมื่อเปิดการผสม.
- คำบรรยาย: เปิด/ปิด, แสดงแหล่งข้อความอัตโนมัติ, รูปแบบ/ตำแหน่ง/ขนาดจากระบบซับเดิม พร้อมตัวอย่างข้อความบนภาพ. ตัวอย่างดีไซน์ต้องไม่อ้างว่าเป็นซับจริงหรือเสียงที่สร้างแล้ว.
- เสียงประกอบ: เปิดเพลงพื้นหลังและSFXแยกกัน มีทางไปค่าที่บันทึกไว้; ปรับระดับเสียงโดยไม่กระทบเสียงพูด. ตัวเลือกเก็บเสียงคลิปผสมกับAPIอยู่ใต้โหมดAPIเท่านั้น.

สรุปท้ายแผง เช่น “เสียงต้นคลิป • ซับจากเสียงจริง • เพลงเปิด • SFXปิด”. แจ้งความพร้อมบริการเสียงและบริการถอดซับแยกกัน ไม่แสดง token. แสดงเหตุผลข้างตัวเลือกที่ไม่รองรับ ไม่แอบเปลี่ยนโหมด.

Responsive: จอกว้าง2การ์ด จอแคบเรียงตั้ง, พื้นที่กดอย่างน้อย44px, ใช้คีย์บอร์ดได้, focusชัด, labelครบ และค่าที่เลือกไม่หายเมื่อย่อหน้าต่าง/เปลี่ยนหน้า.

## สัญญาข้อมูลและการรองรับรุ่นเก่า

- เสนอ `audio_choices.version=2`: mode=`api|source_original|none`; fieldเดิม subtitle/music/sfx/allow_silent/keep_video_audio/video_audio_volume คงไว้. เพิ่ม narration_volume หากเปิดให้ปรับเสียงAPIโดยแยกจากต้นคลิป.
- provider ของวิดีโอเก็บแยกจากแหล่งเสียง. ใช้ตัวตรวจ capability ร่วมกันทั้งUI/queue/backend/Extension ไม่กระจาย hardcode Flow หลายจุด.
- อ่านversion1 `flow_original` เป็นความหมาย native ของงานFlowเดิมได้ แต่ไม่แก้manifest/receipt/contextของงานเก่าอัตโนมัติ. ห้ามเปลี่ยน pending prompt fingerprint ระหว่างรันหรือresume.
- การตั้งใหม่ใช้กับงานใหม่/คิวที่ยังไม่ผูกงาน. คิวที่รัน/ผูกงานแล้วล็อกไว้. ปุ่มทำต่อยึดค่าที่บันทึกกับjob ไม่อ่านฟอร์มล่าสุด.
- ไม่มีการสร้างเสียงAPIแทนโดยอัตโนมัติเมื่อเสียงต้นคลิปหาย. ให้ตรวจฉากที่ขาดเสียงและเลือกอย่างชัดเจนว่าจะยอมรับช่วงเงียบหรือทำrevisionเฉพาะส่วน.

## ลอจิกเสียงและซับ

### ต้นฉบับจากคลิป
- สร้างคลิปพร้อมแนวทางเสียงตามชนิดเนื้อหา: สินค้ามีผู้รีวิวให้พูดภาษาไทยพร้อมการแสดง; เรื่องเล่า/ละครใช้บทพูดและผู้พูดของฉาก ไม่บังคับทุกงานเป็นผู้รีวิวหน้ากล้อง.
- รักษาเสียงที่ดาวน์โหลดมา ไม่ใช้`-an`, ไม่เปลี่ยนความเร็ววิดีโอจนเสียงเพี้ยน, ตรวจ stream/duration และตรวจความเงียบจริง แยกไม่มีaudio trackกับมีtrackแต่เงียบ. ไม่มีคำพูดไม่ได้แปลว่าไฟล์เสียเสมอไป.
- เปิดซับ: ถอดจากเสียงพูดจริงก่อนผสมเพลง/SFXที่เพิ่มใหม่; รักษาoffsetหลังตัดต่อ/transition/intro. ไม่ยัดบทเดิมแทนคำที่ผู้สร้างวิดีโอพูดไม่ครบ.
- ปิดซับ: ไม่เรียกบริการถอดเสียง. เปิดเพลงปิดเพลงมีผลกับเพลงที่โปรแกรมเพิ่มเท่านั้น ไม่รับประกันลบเพลงที่ฝังในต้นคลิป.

### API SmartSub
- ใช้เส้นทางสร้างเสียงSmartSubปัจจุบันและเสียงที่ตั้งไว้ ตรวจcredentialโดยไม่บันทึกลงjob/log.
- ยึดบทของฉากที่ผ่านแล้ว; บันทึกคิว/idempotencyและนำเสียงเดิมกลับมาใช้เมื่อทำต่อ ไม่ส่งซ้ำ.
- ซับยึดเสียงพากย์จริงพร้อมบทที่อนุมัติและการจัดเวลาเดิม ไม่ถอดเสียงบรรยากาศปน. เพลง/SFX duckingตามเสียงพูด.
- ค่าเริ่มต้นไม่ผสมเสียงพูดต้นคลิปซ้อน. หากผู้ใช้เลือกเก็บต้นคลิปด้วย แสดงเตือนเสียงพูดทับกันและให้ระดับเสียงแยก; ไม่กล่าวอ้างว่าแยกเสียงพูดออกจากบรรยากาศได้โดยไม่มีระบบแยกเสียง.

## งาน Extension และแต่ละ provider

- Google Flow: ใช้การส่ง/แนบ/รอ/ดาวน์โหลดที่ทำงานอยู่แล้ว ปรับเฉพาะaudio intentในpackage/prompt และหลักฐานผลเสียง. ห้ามเขียนSendใหม่เพื่องานUIนี้.
- Meta: เปลี่ยนpromptให้ขึ้นกับโหมดเสียง โดยคงsilentสำหรับงานAPIที่บันทึกเดิม. ทดลองแบบจำกัดขอบเขตผ่านโปรแกรมเพื่อพิสูจน์native speech/audioจริงก่อนเปิดตัวเลือกให้ผู้ใช้. หากบริการ/บัญชี/ผลไฟล์ไม่รองรับต้องบอกตรง ๆ; native Meta ยังไม่ใช่ความสามารถที่พิสูจน์แล้ว.
- ChatGPT/Gemini: ผู้วางแผนได้รับโหมดเสียงที่ถูกต้อง แยกบทผู้พูดกับผู้บรรยายและคำสั่งภาพ; ไม่เปลี่ยนSend/retry/ownershipของภาพที่ทำงานดีอยู่.
- ไฟล์ผลลัพธ์ต้องตรวจเสียงที่desktopด้วยmedia probeจริง ไม่ถือว่าข้อความAIว่า “มีเสียง” เป็นหลักฐาน.
- หากแก้Extensionจริง ต้องออกversionใหม่และจับคู่desktopตามกฎโปรเจกต์ ไม่สรุปล่วงหน้าว่าจำเป็นต้องแก้ทุกไฟล์หรือทุกprovider.

## สถานะงานที่ต้องแก้ร่วมกัน

ใช้job/runและลำดับphaseแยกจากเปอร์เซ็นต์. เก็บเปอร์เซ็นต์ไม่ถอยได้ แต่ต้องอัปเดตข้อความขั้นใหม่ที่ถูกเจ้าของได้. สำหรับMeta/API: ภาพ → วิดีโอ → เสียง → ซับ/ประกอบ → ปก → ตรวจและบันทึกFinal. อย่าแสดงกำลังทำเสียงก่อนvideoผ่าน หรือ100%ก่อนปกที่ร้องขอสำเร็จ.
