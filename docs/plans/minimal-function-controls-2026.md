# แผนปรับปุ่มเลือกฟังก์ชัน SmartFlow AI

วันที่: 2026-09-21

## รูปแบบที่ผู้ใช้เลือก

ยืนยันวันที่ 2026-09-21: ใช้แบบ 1 เป็นรูปแบบหลักสำหรับการเปิด/ปิดฟังก์ชัน ชื่อและคำอธิบายอยู่ซ้าย สถานะเปิด/ปิดและสวิตช์อยู่ขวา กดได้ทั้งแถว พร้อมแอนิเมชันเบา ๆ

คงปุ่มแบ่งส่วนสำหรับตัวเลือกที่เลือกได้อย่างเดียว และเครื่องหมายเลือกสำหรับการเลือกหลายคลิป ไม่เปลี่ยนทุก checkbox เป็นสวิตช์ ผู้ใช้สั่งลงมือแล้ว จึงเพิ่มชุดหน้าตากลางแบบ display-only โดยไม่แก้ controller หรือ Extension

## เป้าหมาย

ทำให้การตั้งค่าก่อนสร้างคลิปอ่านง่าย มินิมอล และกดสะดวก ลดช่องติ๊กเล็ก ๆ ที่เรียงปนกับคำอธิบายหลายระดับ โดยไม่เปลี่ยนความหมาย ค่าเริ่มต้น หรือการส่งค่าของฟังก์ชันเดิม

ในรอบวางแผนเดิม ไม่อัปเดต Extension ไม่รีโหลดโปรแกรม ไม่เริ่มงาน ไม่แก้คิว และไม่แตะงานที่กำลังสร้างอยู่ ตอนนั้นตรวจสถานะแบบอ่านอย่างเดียวพบ Story กำลังทำงาน และคิวพักอยู่ จึงทำตัวอย่างแยกจากหน้าจอจริงทั้งหมด ส่วนรอบลงมือภายหลังตรวจไม่พบ bridge ที่เปิดอยู่ จึงทดสอบ source แยกโดยไม่เปิดโปรแกรมแทนผู้ใช้

## ตัวอย่าง 3 แนว

ใช้ข้อมูลและสถานะเริ่มต้นเดียวกันเพื่อเปรียบเทียบ: เสียงจากคลิป, เล่าเรื่องก่อนรีวิวเปิด, ตัวละครปิด, คำบรรยายเปิด, เพลงปิด ค่าในตัวอย่างไม่ใช่คำสั่งเปลี่ยนค่าเริ่มต้นของโปรแกรม

| แบบ | หน้าตา | ข้อดี | ข้อแลกเปลี่ยน |
| --- | --- | --- | --- |
| 1 — สวิตช์เป็นแถว | ชื่อ + คำอธิบายสั้นซ้าย, เปิด/ปิดและสวิตช์ขวา | อ่านไล่ลงมาเร็ว เหมาะกับหลายฟังก์ชัน ดูสงบ | เด่นน้อยกว่าการ์ด |
| 2 — การ์ดเลือกฟังก์ชัน | การ์ดกดได้ทั้งใบ พร้อมเครื่องหมายเลือกและข้อความสถานะ | เห็นกลุ่มฟังก์ชันชัด เหมาะกับตัวเลือกหลักไม่กี่ตัว | ใช้พื้นที่มาก ถ้าใช้ทุกหน้าจะรกอีก |
| 3 — ปุ่มเลือกกระชับ | ปุ่มสั้นมีไอคอน ชื่อ และเปิด/ปิด | ประหยัดพื้นที่ เหมาะกับผู้ใช้ที่คุ้นเคย | คำอธิบายถาวรมีน้อย ไม่เหมาะกับสิทธิ์หรือฟังก์ชันซับซ้อน |

ข้อเสนอ: ใช้แบบ 1 เป็นหลัก ส่วนประเภทที่เลือกอย่างเดียว เช่น แหล่งเสียง ใช้ปุ่มแบ่งส่วนหรือการ์ด radio; แบบ 2 ใช้เฉพาะการเลือกโหมดหลัก และแบบ 3 ใช้กับตัวเลือกสั้นที่รู้ความหมายชัดแล้ว ไม่ใช้ทุกแบบปนกันในกลุ่มเดียว

## กติกาการเลือกที่ต้องแยกให้ชัด

1. เปิด/ปิดฟังก์ชันอิสระ: ใช้สวิตช์ที่กดได้ทั้งแถว มีคำว่าเปิด/ปิด ไม่ใช้สีเพียงอย่างเดียว
2. เลือกอย่างเดียว: ใช้ radio ในปุ่มแบ่งส่วน เช่น เสียงจากคลิป / SmartSub; ไม่แปลงเป็นสวิตช์สองอันที่เปิดพร้อมกันได้
3. เลือกหลายคลิป/หลายสินค้า: คง checkbox แบบเลือกแถวหรือการ์ด ปรับหน้าตาให้เรียบร้อย และรองรับเลือกบางส่วน (`indeterminate`) ของปุ่มเลือกทั้งหมด
4. การยินยอม/สิทธิ์: คงการกดยืนยันอย่างชัดเจน ไม่มีการเปิดอัตโนมัติ และไม่ซ่อนข้อความสำคัญในเมนูเพิ่มเติม
5. ตัวเลือกที่ใช้ไม่ได้: แสดงสถานะปิดใช้งานพร้อมเหตุผล ไม่หายไปเฉย ๆ และห้ามกดทะลุ
6. ค่าที่มีผลเฉพาะงานใหม่: มีคำอธิบายสั้นว่าไม่แก้งานที่กำลังรัน; ไม่แสดงให้เข้าใจว่าเปลี่ยนงานเก่าได้ทันที

## หน้าตาและการเคลื่อนไหว

- รักษาเอกลักษณ์พื้นเข้มของ SmartFlow และสีฟ้าสำหรับสถานะที่เลือก ลดกรอบเรืองแสงและการใช้หลายสีในกลุ่มเดียว
- ชื่อฟังก์ชันชัด คำอธิบาย 1 บรรทัดเมื่อพอได้ ไม่ย่อฟอนต์เพื่อให้ข้อความยาวยัดลงบรรทัดเดียว
- ใช้ไอคอนเส้นจากชุดเดียวกัน ไม่ผสม emoji รูปภาพและไอคอนคนละน้ำหนัก
- เป้าหมายพื้นที่กดทั้งแถวไม่น้อยกว่า 44px; อ่านชื่อและกดด้วยคีย์บอร์ดได้ มี focus ชัด
- สวิตช์เลื่อนประมาณ 180ms, สีพื้นเปลี่ยนอย่างนุ่มนวล ไม่มีไฟกระพริบหรือแอนิเมชันวน และเคารพ reduced motion
- จัดลำดับ: โหมดหลัก → ฟังก์ชันเสริม → ตัวเลือกเพิ่มเติม → ปุ่มหลัก ไม่เพิ่มปุ่มแยกหลายปุ่มในแต่ละแถว
- คงตัวเลือกขั้นสูงไว้ในส่วนพับได้ แต่ไม่ซ่อนข้อผิดพลาด ข้อจำกัด หรือข้อมูลจำเป็นในการตัดสินใจ
- ในโปรแกรมจริงใช้คำสั่งเริ่มงานเดิม ในตัวอย่างใช้ปุ่ม “ดูสรุปที่เลือก” ซึ่งไม่เรียก backend

## แผนลงมือเมื่อผู้ใช้เลือกรูปแบบ

### 1. สร้างชุดควบคุมหน้าตากลาง

- กำหนด class เฉพาะสำหรับ switch row, radio segments, selectable card, selection checkbox
- ใช้ native input เดิมด้านใน รักษา id, name, value, data attributes, `.checked`, change event และ disabled state
- ไม่ใช้ CSS ครอบ `input[type=checkbox]` ทั้งโปรแกรม เพราะ checkbox คิวและ checkbox ยินยอมไม่ควรกลายเป็นสวิตช์
- ไม่ทำสำเนาค่าอีกชุดใน DOM หรือผูก click และ change ซ้ำจนค่าพลิกกลับ

### 2. เริ่มที่หน้าทำคลิปสินค้า Shopee

- ตัวเลือกเล่าเรื่องก่อนรีวิว / ตัวละคร / คำบรรยาย / เพลง / เอฟเฟกต์เสียง
- แหล่งเสียงยังเลือกได้หนึ่งอย่าง ต้องรักษาโหมดเสียงขั้นสูงและค่าที่บันทึกไว้
- ตรวจค่าใน form, payload งานเดี่ยว และ payload นำเข้าคิวก่อน–หลังให้ตรงกัน
- การตั้งค่า job ต้องถูก snapshot ตามพฤติกรรมเดิม ไม่ไหลไปเปลี่ยนงานที่เริ่มแล้ว

### 3. ขยายไปหน้าที่ใช้ชุดเดียวกัน

- Story Shorts และหน้าที่ mount `media_audio.js` → Presenter/Drama และการตั้งค่าที่เกี่ยวข้อง
- หน้า Shopee posting: ปรับ reuse/AI label เป็นสวิตช์จริง แต่คงค่าเริ่มต้นและความหมายเดิม
- รายการคลิปและคิว: ปรับ checkbox ให้เป็นแถวเลือกที่อ่านง่าย ไม่เปลี่ยนตรรกะเลือก/ลบ/เริ่มงาน
- เดินทีละกลุ่ม ไม่เปลี่ยน provider automation, submit/retry, การแนบภาพ หรือ prompt จากงาน UI นี้

### 4. ตรวจรับก่อนอัปเกรดจริง

- เปรียบเทียบ payload เดิมกับใหม่สำหรับทุกตัวเลือก และตรวจงานเดี่ยว/หลายงาน/ทำต่อ/งานที่พัก
- ทดสอบ mouse, Tab, Space, radio arrow keys, ชื่อที่โปรแกรมอ่านหน้าจออ่าน, disabled และเหตุผลที่แสดง
- ตรวจทั้งเปิด/ปิด/เลือกบางส่วน/ใช้งานไม่ได้ และความสัมพันธ์ เช่น โหมดสนทนากับคำบรรยาย
- ทดสอบความกว้างหน้าต่าง, ข้อความไทยยาว, Windows scaling 125%/150%, ค่าที่ถูก restore และแสดงผิดหน้าไม่ได้
- ทดสอบ popup/backdrop/progress เดิมเพื่อป้องกัน CSS ใหม่ทำให้ชั้นหน้าต่างหรือแอนิเมชันเดิมผิด
- จึงบันทึกผลและเตรียมอัปเกรดเมื่อไม่มีงานที่ต้องถูกรบกวน ไม่รีโหลดทับงานที่ผู้ใช้กำลังสร้าง
