# แผนบทพูดและการเล่าแบบมืออาชีพ — SmartFlow

วันที่ 2026-09-28 • สถานะ: วิเคราะห์และวางแผนเท่านั้น ยังไม่แก้ runtime

## เป้าหมายและขอบเขต

ทำให้รีวิว Shopee, นิ้วชี้, เรื่องเล่า และบทสนทนา ฟังเหมือนคนเล่าที่เตรียมเรื่องมาดี ไม่ใช่อ่านรายการคุณสมบัติหรือประกาศโฆษณา ครอบคลุม SmartSub Voice Clone ผ่าน API เดิม กับเสียงที่สร้างมากับคลิป Meta AI / Google Flow โดยรักษาผู้พูด ข้อเท็จจริง โหมดเสียง และเวลาฉากที่ผู้ใช้เลือก

รอบนี้ใช้ smartflow-operator อ่าน source/เอกสารและสถานะสาธารณะแบบ read-only กับแหล่งทางการ ไม่สร้างเสียง/ภาพ/วิดีโอ ไม่ส่งงาน ไม่เปลี่ยนคิว ไม่รีโหลดแอป/Extension ไม่เปลี่ยนบริการ SmartSub และไม่เปิด monitor ที่ผู้ใช้สั่งปิด

ฐานปัจจุบัน: canonical463 รวมฟังก์ชันนิ้วชี้แล้ว; snapshot รอบวางแผนพบ desktop required463 และ Extension connected463 หนึ่งตัว แต่เวอร์ชันตรงกันไม่ใช่หลักฐานคุณภาพเสียงหรือ provider E2E

## สิ่งที่ตรวจพบจริง

1. `core/product_script.py::review_instruction/creative_product_instruction/film_instruction` มีบทสั้น ภาษาพูด ความต่อเนื่อง และข้อห้ามแต่งสเปก/ประสบการณ์ใช้แล้วอยู่แล้ว จึงควรเสริมการกำกับจังหวะจากฐานนี้ ไม่แทนที่ทุกแนวด้วยโฆษณาสูตรเดียว
2. `core/media_audio.py::_flow_audio_instruction` แยก reviewer, narrator, actor, short film และ POV นิ้วชี้ พร้อม exact saved line แต่ระดับการกำกับ delivery ต่างกัน บางทางมีเพียง “clear natural Thai speech” ยังไม่มีสัญญาบุคลิกเสียง/จังหวะรายฉากชุดเดียว
3. `core/external_tts.py::synthesize` ตั้ง `emotion_id=normal`, `speed=1.0` ที่ขอบ API โดยเจตนา เพื่อไม่ให้ค่าจากงานเก่าทำเสียงเพี้ยน มี text/reference/language/engine/silence/idempotency แต่ไม่มีช่อง natural-language style instruction แยก จึงห้ามเอา “พูดอย่างอบอุ่น…” ไปปนใน text และห้ามปลดล็อก emotion/speed เพียงเพื่อเรียกว่าโปร
4. `core/thai_tts.py` เก็บ whitelist `[pause:...]`, `[laughter]`, `[sigh]` และแท็กเสียงบางชนิดไว้ ตรวจแท็กแปลก แปลงตัวเลข/คำอ่าน และยอมให้คำอังกฤษที่ไม่รู้จักผ่านได้; newline/whitespace ถูกยุบ จึงใช้การขึ้นบรรทัดใหม่อย่างเดียวเพื่อรับประกันการเว้นจังหวะไม่ได้ การผ่านตัวกรองของเราไม่ได้พิสูจน์ว่า engine ปัจจุบันสร้างทุกแท็กได้ถูกต้อง ห้ามอ้างรองรับ SSML ทั่วไป
5. `core/scene_voice.py::render_scene_asset` ส่ง text ราย turn กับ reference ที่เลือก ใช้ ledger กันส่งเสียเงินซ้ำ แต่เรียกตัวเตรียมคำอ่านโดยไม่ส่ง pronunciation_notes ต่างจาก `core/story_finisher.py::_subtitle_script` ซึ่งส่ง notes และในเส้นทางรายฉากนี้ยังไม่ได้อ่าน `pause_after` จาก turn โดยตรง นี่เป็นช่องว่างจาก source ที่ควรมี fixture ก่อนแก้ ไม่ใช่ข้อสรุปว่าคลิปจริงทุกงานอ่านผิด
6. `core/story_manager.py` ยังมี prompt บาง branch ขอคำอ่านไทยทั้งหมด ขณะที่ normalizer ปัจจุบันยอมรับอังกฤษ ต้องตรวจ branch จริงของสัญญาใหม่ให้ไม่ส่งคำสั่งขัดกัน ห้ามคืน English-only blocker ที่เคยแก้แล้ว หรือแก้บทเก่าที่อนุมัติไว้
7. `core/flow_speech_quality.py` ตรวจวลีที่พูดซ้ำจาก transcript และขอบเขตฉากเท่านั้น `no_clear_repeat` ไม่ได้หมายความว่าเล่าดี ออกเสียงถูก คนพูดถูก หรือ lip-sync ตรง และรอบนี้ยังไม่ได้ฟังคลิปตัวอย่างเพื่อยืนยันปัญหาน้ำเสียงจริง

## แนวคิดหลัก: แยก 3 ชั้น

| ชั้น | หน้าที่ | สิ่งที่ต้องไม่ปน |
| --- | --- | --- |
| บทพูด | คำที่ผู้ฟังจะได้ยินจริง แยกตามฉาก/turn | @ชื่อ, คำสั่งกล้อง, น้ำเสียง, คำอธิบายฉาก |
| การกำกับ | ใครพูด พูดกับใคร บุคลิก จังหวะ คำเน้น และคนที่ต้องเงียบ | ไม่ให้กลายเป็นเสียงอ่านหรือบทเพิ่ม |
| ตัวแปลงบริการ | ส่ง SmartSub เป็น text+voice mapping; Meta/Flow เป็น exact dialogue+direction | ไม่ใช้แท็ก/ความสามารถของบริการหนึ่งกับอีกบริการโดยเดา |

ใช้บทต้นฉบับที่บันทึกแล้วเป็นแหล่งเดียว การปรับคำอ่านเป็นข้อความสำหรับเสียงอีกชั้นที่ตรวจย้อนกลับได้ ไม่ให้ AI เขียนบทใหม่ซ้ำตอนสร้าง motion หรือกู้ฉาก

## กติกาการเขียนที่เสนอ

เพิ่มเติมจากผู้ใช้: ตัวอย่างคลิปล่าสุดพูดลักษณะ “มีความยาวที่ระบุเอาไว้ในสินค้า” ทำให้เหมือนอ่านข้อมูลหลังบ้าน ไม่ใช่รีวิว ชุดคำสั่งฉบับขยายอยู่ที่ [professional-speech-prompt-pack-20260928.md](professional-speech-prompt-pack-20260928.md) แยกการคัดข้อเท็จจริงออกจากบทที่จะพูด พร้อมตัวอย่างก่อน/หลังและกติกาห้ามอ่าน metadata ยังไม่ได้ตรวจไฟล์คลิปล่าสุดหรือระบุ job จึงยังไม่ยืนยันว่ามาจาก branch ใด

หลักเพิ่ม: ข้อมูลชัดให้เล่าตรงและเป็นธรรมชาติ ข้อมูลไม่รู้ไม่แต่งและไม่เติมประโยคอ้างรายการสินค้า ข้อจำกัดสำคัญต่อการตัดสินใจยังต้องบอกอย่างตรงไปตรงมา ห้ามแก้ด้วยการลบคำเตือนทั้งหมดหรือเปลี่ยนความไม่แน่นอนให้เป็นคำรับประกัน

- “มืออาชีพ” หมายถึงชัดเจน มีจุดมุ่งหมายและจังหวะ ไม่ได้บังคับภาษาทางการ/เสียงผู้ประกาศ ใช้โทนที่เลือกอยู่แล้ว ไม่เพิ่มหน้าตั้งค่าซ้ำกับตัวเลือกแนวเรื่องเดิม
- รีวิว: เปิดด้วยสิ่งที่คนดูสนใจ → ชี้รายละเอียด/สาธิตที่มีหลักฐาน → อธิบายความหมายต่อการใช้งาน → สรุปให้ตัดสินใจ ไม่ท่องชื่อสินค้ายาวซ้ำทุกฉาก
- นิ้วชี้: ภาษาเหมือนผู้ถือกล้องชวนดูจุดตรงหน้า เชื่อมคำกับสิ่งที่มือชี้จริง เสียงหลังกล้องคนเดิม ไม่เห็นหน้า ไม่ขอ lip-sync หรือเพิ่มผู้รีวิวคนใหม่
- เรื่องเล่า: เปิดประเด็น → เหตุและผล/พัฒนาการ → จุดคลี่คลาย → จบตามตัวเลือกเดิม แต่ละฉากเพิ่มข้อมูล ไม่เริ่มฮุกใหม่ทุกฉาก
- บทสนทนา: ประโยคตอบโต้มีเหตุผลและเข้าบุคลิก ไม่ให้ตัวละครพูดบทบรรยายยาวหรืออธิบายทุกสิ่งที่คนดูเห็น รักษาผู้ฟังและลำดับ turn
- หนึ่งวลีมีหนึ่งประเด็น ใช้ประโยคที่อ่านออกเสียงลื่น เว้นจังหวะก่อนข้อสำคัญและตอนเปลี่ยนเรื่อง ไม่ใส่ “เอ่อ/อ่า” สุ่มเพื่อทำเหมือนคนจริง ไม่ใส่เสียงหัวเราะ/ถอนหายใจทุกฉาก
- ไม่แต่งการซื้อ/ทดลองใช้ ผลทดสอบ ราคา โปรโมชัน หรือคำรับรอง ไม่มี “ดีที่สุด/รับประกัน” ถ้าไม่มีข้อมูลรองรับ ภาษาบุคคลที่หนึ่งไม่เท่ากับสิทธิ์แต่งประสบการณ์ส่วนตัว
- CTA เป็นไปตามงานเดิมเท่านั้น ปิดไว้ต้องไม่เติม เปิดไว้ให้มีครั้งเดียวในจุดจบที่เหมาะสม ไม่เปลี่ยนแนวหนังสั้น/ละครให้เป็นรีวิว
- บทที่ผู้ใช้ระบุว่า exact/อนุมัติแล้วต้องคงคำเดิม เสนอคำย่อเมื่อเกินเวลาได้ แต่ห้ามแก้เองเพื่อให้ผ่าน
- คำนวณจากเวลาคลิปของฉากและ provider/model ที่บันทึกจริง ไม่ hard-code ทุกฉากว่า 8 วินาที เผื่อจังหวะหายใจ/ปฏิกิริยา ไม่เร่งเสียงให้ยัดบท การประมาณจำนวนพยางค์เป็นสัญญาณเตือน ไม่ใช่หลักฐานเวลาพูดจริง

## วิธีใช้กับแต่ละเสียง

### SmartSub Voice Clone

- ใช้เสียงหลัก/เสียงรายตัวที่ผู้ใช้เลือก คง `normal / 1.0x` และ reference เดิม ไม่สลับเสียงอัตโนมัติ
- ปรับความลื่นที่บทและการแบ่งวลีเป็นอันดับแรก ทำตัวแปลงร่วมสำหรับ scene voice / review / subtitle ให้ใช้ notes และข้อความคำอ่านเดียวกัน รองรับอังกฤษเดิม ไม่บังคับแปลงชื่อใหม่แบบเดา
- แยก spoken text ที่สะอาดจากข้อความ TTS ที่มี pause ที่รองรับ ซับไม่แสดงแท็กและคำกำกับ; อย่าใช้การลบ @ ทั้งก้อนจนคำอีเมลหรือข้อความจริงหาย
- เคารพ pause ที่มีอยู่แล้ว ก่อนเพิ่มแท็กอัตโนมัติต้องตรวจ engine/capability จริง ใช้ plain text เป็น fallback ถ้ายังไม่ยืนยัน ไม่เปลี่ยนจาก engine auto หรือเปิดอารมณ์แรงเอง
- แบ่งคำขอตาม ledger/เพดาน 2,000 ตัวอักษรเดิม ตัดตรงจบวลีเท่าที่ได้ ไม่แบ่งเป็นคำขอทุกประโยคจนเสียงและจำนวนคิวกระโดด
- วัดความยาวเสียงจริงก่อนประกอบตามโฟลว์เดิม ไม่ปรับความเร็ว/ตัดคำท้ายเพื่อซ่อนบทล้น และไม่สร้างเสียงใหม่เพียงเพราะมี metadata การกำกับเพิ่ม

### Meta AI และ Google Flow: เสียงในคลิป

- เติม AUDIO PERFORMANCE block สั้นเพียงหนึ่งชุดหลัง motion ผ่านการตรวจ ไม่ฝาก helper แต่งบทซ้ำ
- ระบุ exact line ในเครื่องหมายคำพูด, speaker/listener, on-screen/off-camera, โทนที่สัมพันธ์กับเรื่อง, จังหวะไม่รีบ, ชัดแต่ไม่ตะโกน/โอเวอร์ และพูดครั้งเดียว ห้ามเสียงแทรกในช่วงคนอื่นพูด
- เชื่อมกับแผน `docs/plans/video-speaker-binding-20260928.md`: @พ่อ เป็นป้ายอ้างตัวละครและบท ไม่ใช่คำที่ให้อ่าน และไม่ถือว่าใส่ @ แล้วล็อกเสียง/คนได้แน่นอน
- รักษา voice persona รายงาน/ซีรีส์ แต่เรียกสิ่งนี้ว่า “คำกำกับความต่อเนื่อง” ไม่อ้างว่า native provider ใช้ voice reference แบบ SmartSub โดยอัตโนมัติ
- API dubbing ต้องไม่ขอ native speech ซ้อน; visual-only ยังไม่มีเสียงพูด; music/SFX ใช้ตัวเลือกเดิม ไม่สั่งปิดหรือเปิดเพลงทั้งคลิปโดยพลการ
- รอบกู้บริการ/การอ่านผล/บันทึก Meta/Flow ใช้บท+speaker+delivery snapshot เดิม ไม่เปลี่ยนคำพูดเพื่อผ่านบริการหรือเพิ่ม paid retry loop จากคะแนนสไตล์ ยกเว้นเส้นทาง creative_revision_version1 ที่ได้รับอนุญาตให้เขียนฉากใหม่อยู่แล้ว: ต้องใช้บทและ delivery ของ revision ใหม่ที่ desktop ตรวจผ่านเฉพาะฉากนั้น ไม่แนบเสียงเก่าทับบทใหม่ ดูแผนอัปเดตรวมด้านล่าง
- Google voice/character references เป็นความสามารถแยกตาม mode/model ตรวจเส้นทางจริงก่อนเสนอใช้ ไม่เปลี่ยน Frames เป็น Ingredients หรือเปลี่ยนโมเดลเพื่อให้ได้เสียงใหม่เอง ส่วน Meta ยังไม่มีหลักฐานในรอบนี้ว่า arbitrary @name ของช่องสนทนาที่เราใช้เป็น native voice binding

## สัญญาข้อมูลและการลงมือภายหลัง

เพิ่ม versioned speech delivery snapshot เฉพาะงานใหม่ที่เปิดใช้ ไม่เปลี่ยนความหมาย fields เดิม ตัวอย่างแนวข้อมูล:

```text
speech_delivery_version: 1
profile: resolved from saved product/story tone, not current global settings
scene: index + effective duration + spoken-text revision/hash
turn: existing speaker ID/name + listener + placement + exact text
delivery: pace, restrained emotion, emphasis phrases, pauses
provider capabilities: only controls verified for the selected path
```

emotion ใน delivery เป็นคำกำกับ native performance ไม่ใช่ emotion_id ที่จะส่ง SmartSub; emphasis ต้องอ้างวลีที่มีใน text จริง ค่าจังหวะต้องมีขอบเขต ไม่ยอมให้ AI สร้าง metadata ที่เปลี่ยน permission/queue/credits

ลำดับเสนอ:

1. **ตัวเขียนบทกลางและ fixture ก่อน:** helper pure function เช่น `core/speech_delivery.py` เชื่อม `product_script`, `storytelling`, `story_manager` และ Product path ที่ใช้จริง ยึดคำพูดผู้ใช้ > script contract > generic default; remove/replace conflicting instructions เฉพาะ branch ใหม่ ไม่ต่อ prompt หลายชุดขัดกัน
2. **ตัวแปลงสองทาง:** API เตรียมคำอ่าน/วลีร่วม; native ประกอบเสียงที่ `media_audio`, `story_performance`, `product_pointing` และส่งต่อ `flow_motion_plan`, `meta_video`, `meta_redesign` แบบไม่เติมบทซ้ำ การตรวจ Web result/repair ต้องรู้ fields ใหม่ถ้าข้อมูลเดินผ่าน Extension
3. **อายุข้อมูลและ resume:** freeze profile/lines/voice mapping เมื่อรับบท ให้ identity ของงานใหม่รวม effective speech payload/capability version พอป้องกันเสียงเก่าคนละบท; งานเก่าใช้ identity เดิม ไม่ invalidation เสียงที่จ่ายแล้วจาก default ใหม่ การเปลี่ยนเฉพาะคำกำกับ native ต้องไม่เปลี่ยน TTS key ที่ payload เดิม
4. **คงการทำทีละฉาก:** ภาพ N → วิดีโอ N → บันทึกผลตาม gate เดิม → N+1; ไม่เปลี่ยน Meta receipt gate เป็น Flow rendered-audio flag หรือลากงานสำเร็จกลับไปสร้างใหม่ ทุกขั้นซ่อมเฉพาะส่วนค้าง
5. **ตรวจผล/ส่งมอบ:** offline ก่อน แล้วฟังตัวอย่างสั้นตามขอบเขตเครดิตที่ผู้ใช้อนุญาตภายหลังเท่านั้น หากต้องแก้ Extension ให้จับคู่รุ่นกับ desktop และแพ็ก immutable รุ่นถัดไปตามสถานะจริง ห้ามสมมติเลขรุ่นตอนนี้/ทับ463/ติดตั้ง Chrome แทนผู้ใช้

## แผนทดสอบและเกณฑ์ผ่าน

- Matrix หลัก: รีวิวปกติ / นิ้วชี้ / narrator / solo / dialogue / หนังสั้น / visual-only × API / Meta native / Flow native เท่าที่ระบบอนุญาตจริง ไม่เปิดโหมดผสมใหม่เพื่อให้ครบตาราง
- ตรวจคำพูดไม่มี speaker label/@tag/คำสั่งแสดงอารมณ์หลุดไป TTS; pause whitelist ไม่แตกกลาง chunk; unknown English ผ่าน; notes ตรงกันระหว่างเสียง/preview/subtitle
- exact line มีใน native prompt ครั้งเดียว; คนฟังเงียบเฉพาะ turn ไม่ถูกสั่งเงียบทั้งคลิปเมื่อถึงบทตน; POV ไม่ถูกบังคับเห็นปาก; ไม่มีเสียงพากย์ซ้อนใน API mode
- รีวิวไม่แต่ง fact/testimonial; story tone/CTA/silent/จำนวนฉาก/ระยะเวลา/ผู้พูดไม่เปลี่ยน; metadata ที่ไม่ครบไม่ทำให้บทรอดผ่านด้วยผู้พูดเดา
- Legacy snapshot byte/semantic parity, saved-media reuse, restart/idempotency และ recovery exact-owner ผ่าน งานที่มีเสียงพร้อมไม่ถูกส่งสร้างซ้ำ
- ตรวจคุณภาพไฟล์ด้วยเครื่องมือเดิม: อ่านได้ มีเสียงตามโหมด ระยะเวลาไม่ตัดคำ/ซ้อนเสียง; transcript ใช้ตรวจคำหาย/เพิ่ม/ซ้ำตามความมั่นใจ อย่าอ้างว่า ASR พิสูจน์คนที่ขยับปากหรือบุคลิกเสียง
- “เล่ามืออาชีพ” ให้ฟังประเมินความชัด ความเป็นธรรมชาติ จังหวะ ความต่อเนื่อง และความตรงบท แยกจาก structural pass; ไม่ทำ subjective score เป็น error ใหม่ที่หยุดคิวหรือสั่งสร้างซ้ำไม่จำกัด
- ยังไม่มี live sample/ผลฟัง A/B ในรอบนี้ จึงยังรับประกันคุณภาพเสียง ภาษาไทย หรือ lip-sync 100% ไม่ได้

## ตัวอย่างเป้าหมาย (สมมติ ไม่ใช่ข้อมูลสินค้าของผู้ใช้)

หากข้อมูลยืนยันเพียง “กล่องมีฝาใสและสามช่อง”:

บทพูด: “จุดที่อยากให้ดูคือฝาใสครับ มองเห็นของด้านในได้เลย ส่วนด้านในแบ่งเป็นสามช่อง แยกของแต่ละอย่างได้เป็นสัดส่วน”

คำกำกับที่แยกออกมา: ผู้รีวิวหลังกล้องคนเดียว น้ำเสียงเป็นมิตรและมั่นใจ เน้น “มองเห็นของด้านใน” เบา ๆ พักเมื่อเปลี่ยนจากฝาไปช่องภายใน ไม่มีเสียงคนอื่น ไม่มีคำอ้างว่าเคยใช้หรือประหยัดเวลาได้กี่เท่า

ตัวอย่างนี้เป็นบทสำหรับหลายฉากตามเวลาจริง ไม่ใช่คำสั่งยัดทั้งหมดในคลิปสั้นฉากเดียว SmartSub ได้เฉพาะบท/คำอ่านที่เตรียมแล้ว; Meta/Flow ได้บทฉากนั้นพร้อมคำกำกับแยก

## แหล่งทางการที่ใช้ประกอบการวางแผน

- [Google DeepMind: Veo prompt guide](https://deepmind.google/models/veo/prompt-guide/) แนะนำระบุเสียง การกระทำ และบทของตัวละคร รวมถึงแยก sound cues ได้ สนับสนุนโครงสร้าง prompt ไม่ใช่การรับประกันผล
- [Google Cloud: Veo3.1 prompting guide](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1/) ระบุ dialogue ในเครื่องหมายคำพูด และแยก SFX/ambient; คู่มือ API ไม่ใช่หลักฐานว่า UI/บัญชี Flow ของผู้ใช้มีฟีเจอร์ครบ
- [Google Flow Help: Create videos](https://support.google.com/flow/answer/16353334?hl=en) ระบุ voice references ใน Omni Flash/Ingredients และข้อจำกัดว่าโหมดอื่นใช้ไม่ได้ ต้อง capability-check ก่อนเชื่อม ไม่ส่ง `@Voice` เปล่า ๆ แทนการเลือก asset
- [Google Flow Help: Manage characters](https://support.google.com/flow/answer/16935308?hl=en) มีการเลือกเสียงให้ character; ยังไม่ใช่ฟังก์ชันที่ SmartFlow ใช้แล้วโดยอัตโนมัติ
- [Meta: AI for video scripting](https://ai.meta.com/learn/ai-creativity/ai-for-video-scripting-how-to-create-high-quality-content-faster/) ข้อมูลทางการที่ค้นพบแนะนำกำหนดโทนและพัฒนา hook; ใช้สนับสนุนการเขียนบท ไม่ใช่การรับรอง speech controls ของ Meta web
- [Meta Vibes](https://ai.meta.com/vibes/) ระบุ dialogue/voiceover ระดับผลิตภัณฑ์ แต่ไม่ยืนยัน arbitrary character tags หรือ voice locking ของช่องสนทนาที่ Extension ใช้
