# แผนเพิ่มโหมด “หนังสั้นโฆษณา — เล่าเรื่องแล้วค่อยเผยสินค้า”

วันที่: 2026-09-21
สถานะ: ผู้ใช้อนุมัติและเพิ่มลง source คู่ Extension 0.15.395 แล้ว ทดสอบรวมผ่าน 2,005 รายการ; ยังไม่ทดสอบสร้างคลิปจริง ดู docs/reports/product-short-film-395.md

## เป้าหมายของผู้ใช้

เพิ่มโหมดแยกจาก “เล่าเรื่องก่อน รีวิวแบบเป็นธรรมชาติ”: เปิดด้วยเรื่องที่ยังไม่พูดถึงสินค้า มีตัวละคร เป้าหมาย เหตุการณ์ และจุดชวนติดตาม จากนั้นให้สินค้ามีบทบาทอย่างสมเหตุสมผลในบางช่วงของเรื่อง จบเรื่องให้คนดูรู้สึกว่าได้ดูหนังสั้นก่อนปิดท้ายด้วยคำชวนดูสินค้าที่ตะกร้า

ไม่ใช่รีวิวที่เปลี่ยนประโยคเปิด ไม่ใช่เอาเรื่องสุ่มที่ไม่เกี่ยวข้องมาตัดเข้าภาพขายสินค้า และไม่ใช่กำหนดให้ทุกฉากโชว์สินค้า

## หลักฐานจาก source ปัจจุบัน

- `core/product_script.py::review_instruction` ใช้ first-person fictional reviewer; เสียง native บังคับผู้รีวิวที่มองเห็นพูดกับกล้อง และมีข้อความไม่บังคับขาย/ไม่เติม CTA
- `core/product_story.py::story_brief` ใน review branch ยังขอ visible product action ในแต่ละ scene_prompt ซึ่งตึงกับข้ออนุญาตให้ไม่เน้นสินค้าในฉากเปิด
- `core/story_manager.py::_write_request` ตั้งบทเป็นคำพูดของผู้รีวิว และระบุฉากสุดท้ายไม่เติมคำขาย/CTA สำหรับโหมดเดิม
- `browser_extension/chatgpt.js::productScriptRepairInstruction` รับเฉพาะ style เดิม version1; โหมดใหม่ต้องคงบท/แนวหนังระหว่างแก้ JSON ด้วย
- motion helper ใน `browser_extension/chatgpt.js` มีเส้นทาง AUDIO PERFORMANCE ที่สั่ง visible reviewer พูดกับกล้อง; ต้องแยกจากการแสดงในเรื่อง ไม่ให้บทหนังกลับกลายเป็นรีวิวตอนทำวิดีโอ
- `core/flow_motion_plan.py` และ StoryManager มี automatic engagement CTA หลายทาง ต้องไม่ให้โหมดใหม่ถูกเติมกดหัวใจ/คอมเมนต์ หรือถูกลบ CTA สินค้าที่อนุมัติแล้ว

นี่เป็นข้อจำกัดที่ยืนยันจากโค้ด ไม่ใช่การยืนยันคุณภาพหรือสาเหตุเฉพาะของคลิปล่าสุด เพราะรอบนี้ยังไม่ได้เปิดคลิปนั้นดู

## หน้าตาในโปรแกรม

รวมไว้ในหัวข้อ “รูปแบบการเล่าเรื่อง” เลือกได้ทีละหนึ่งรูปแบบ:

1. แบบเดิม
2. เล่าเรื่องก่อนรีวิว
3. หนังสั้นโฆษณา — เรื่องนำ สินค้าตาม

ใช้แถวเลือกแบบมินิมอลที่สอดคล้องกับ UX แบบ1 แต่ใช้ native radio เพราะสามโหมดนี้ใช้พร้อมกันไม่ได้ ไม่เพิ่มสวิตช์สองอันที่เปิดชนกัน

ใต้โหมดใหม่มีคำอธิบายสั้น: “เปิดด้วยเหตุการณ์ชวนติดตาม ค่อยเชื่อมสินค้า และชวนดูตะกร้าตอนจบ” แสดงตัวเลือกย่อยเมื่อเลือกโหมดนี้เท่านั้น:

- แนวเรื่อง: อัตโนมัติ (เริ่มต้น), อบอุ่น, ตลก, หักมุม
- “ชวนดูสินค้าที่ตะกร้าตอนจบ” เปิดเป็นค่าเริ่มต้นของโหมดใหม่นี้; ไม่เปลี่ยนค่าในโหมดเก่า
- ใช้ช่องรายละเอียดเดิมสำหรับแนวเรื่อง ไม่สร้างกล่องพรอมต์เพิ่มซ้ำ

รักษาจำนวนฉาก/เสียง/ซับ/โมเดลที่ผู้ใช้เลือก ไม่เปลี่ยนเป็น 6 ฉากหรือเสียง native อัตโนมัติ เสนอแนะ 6 ฉากสำหรับโครงเรื่องที่มีพื้นที่พอ; ถ้าเลือก 3 ฉาก ให้ย่อเป็นเรื่องสั้น 3 จังหวะและแจ้งข้อจำกัด ไม่เพิ่มงานเอง

## การวางเรื่องใหม่

ใช้โครงสร้างเป็นจังหวะ ไม่ใช่สูตร “ปัญหา → สรรพคุณ → ซื้อ” ซ้ำทุกงาน:

1. Hook: เหตุการณ์/คำถาม/ความเข้าใจผิดที่ยังไม่กล่าวชื่อสินค้า ราคา คุณสมบัติ หรือตะกร้า ฉากเปิดไม่จำเป็นต้องมีสินค้าอยู่ในภาพ
2. Setup: รู้ว่าใครต้องการอะไรและมีอุปสรรคอะไร; เหตุการณ์ไม่ใช่เพียงผู้รีวิวเล่าย้อนประสบการณ์
3. Bridge: มีสาเหตุที่ต้องหยิบ ใช้ มองเห็น หรือส่งต่อสินค้า; สัมพันธ์กับเหตุการณ์ที่ปูไว้
4. Product moment: สินค้าเป็นอุปกรณ์ ส่วนหนึ่งของการกระทำ หรือรายละเอียดที่มีความหมาย ไม่ใช่เปลี่ยนเป็นรายการคุณสมบัติ
5. Payoff: คลายคำถามหรือปิดเรื่องจาก hook เดิม ให้ผลลัพธ์ทางเรื่อง/อารมณ์ ไม่อ้างผลทดสอบหรือประสิทธิภาพที่ไม่มีหลักฐาน
6. CTA: หลังเรื่องจบเท่านั้น ประโยคสั้นหนึ่งครั้ง เช่น “ใครสนใจของแบบในเรื่อง จิ้มดูที่ตะกร้าได้เลย” อิงว่ามีลิงก์สินค้าที่บันทึกจริง ไม่รับรองว่าระบบแนบสินค้าสำเร็จแล้ว

สินค้าไม่จำเป็นต้องเป็นผู้แก้ทุกปัญหา: อาจเป็นพร็อพ ของขวัญ ของใช้ร่วมกัน หรือจุดเชื่อมอารมณ์ ขึ้นกับข้อมูลสินค้า ห้ามแต่งคำเคลมส่วนลด สุขภาพ ผลลัพธ์ หรือรีวิวจากผู้ซื้อจริง

ให้ AI คืนเรื่องเดียวที่วางครบแล้ว ไม่คืนหลายพล็อตให้ระบบต้องหยุดเลือก และไม่เพิ่มการถาม AI แยกหลายรอบโดยไม่มีเหตุจำเป็น

## แผนฉากและเสียงต้องไปทางเดียวกัน

- ระบุแผนที่บันทึกต่อฉาก: narrative role, visible action, product presence, เหตุเชื่อมสินค้า, speaker/listener, spoken text และ facts used พร้อมข้อมูล cast/สถานที่เดิม
- ตรวจบทครบและลำดับสมเหตุสมผลก่อนเริ่มสร้างภาพ; ไม่แค่เติมคำสั่งใหม่ท้ายพรอมต์เก่าที่ขัดกัน
- ภาพฉากเปิด/ก่อนเผยสินค้าไม่ต้องยัด product reference เป็นวัตถุในฉาก; reference ใช้รักษารูปลักษณ์เมื่อถึงฉากที่ต้องแสดงสินค้า ไม่ลดการแนบ/ตรวจหลักฐานเดิมโดยพลการ
- Native audio: ตัวละครพูดกับอีกตัวละครหรือทำปฏิกิริยากับเหตุการณ์ ไม่หันมาบรรยายสินค้าให้กล้องทุกฉาก แยก action/direction ออกจาก spoken dialogue และอนุญาตมองกล้องชวนดูตะกร้าในตอนจบที่ระบุไว้
- API SmartSub: เล่าแบบหนังสั้นตามเสียงที่เลือก ไม่สัญญา lip sync และไม่สร้างเสียงพูดซ้อนจากวิดีโอ
- ไม่บังคับปิดซับของโหมดใหม่นี้ เพราะผู้ใช้ยังไม่ได้ขอ คงตัวเลือกซับเดิม; อย่ายืม actor_dialogue_version2 ทั้งก้อนจนเสียง/ซับเปลี่ยนโดยไม่ตั้งใจ
- ถ้าต้องการฉากเงียบ ให้ระบุในแผนชัดและตรวจสัญญาเสียงก่อนรองรับ ไม่ใช้ความเงียบเป็นข้ออ้างยอมรับวิดีโอที่เสียงหายผิดพลาด
- จำนวนผู้แสดงควรน้อยและต่อเนื่อง เริ่มจาก 1–2 คนเมื่อรูปแบบภาพ/เสียงรองรับ ไม่เพิ่มนักแสดงเกินที่จำเป็น และรักษาตัวละครที่ผู้ใช้เลือกไว้

7. `core/flow_replacement.py` และทาง Meta ที่เกี่ยวข้อง: เมื่อจำเป็นต้องซ่อมฉาก ให้รักษา narrative role/ตัวเชื่อมสินค้า/บทอนุมัติ/CTA ไม่แต่งเรื่องใหม่จนฉากข้างเคียงขัดกัน ไม่เพิ่มสิทธิ์ retry หรือวนหลบนโยบาย
8. CTA product เก็บเป็นส่วนหนึ่งของบทฉากท้ายเพียงครั้งเดียว; ทาง ingest/edit/resume/render ต้องไม่เพิ่มซ้ำ และไม่เติม engagement CTA เดิมเข้ามาอีก

ถ้า Extension source เปลี่ยน ต้องออกเวอร์ชันคู่กับ desktop และทดสอบก่อนเสนอให้โหลดเมื่อไม่มีงาน active ห้ามโหลดทับงานที่กำลังทำ

## ตัวอย่างแนวทาง (สมมติสินค้าเป็นโคมไฟตั้งโต๊ะ)

โครงเรื่อง: ลูกสาววัยผู้ใหญ่สงสัยว่าพ่อซ่อนอะไรไว้ทุกคืน สุดท้ายพบว่าพ่อกำลังวาดการ์ดให้เธอ

- เปิด: “พ่อซ่อนอะไรไว้หลังนั้นน่ะ?” ยังไม่พูดถึงโคมไฟ
- ปูเรื่อง: พ่อรีบเก็บกระดาษ ได้ยินเสียงดินสอและมีเศษกระดาษบนพื้น
- เชื่อมสินค้า: อีกคืนเห็นพ่อนั่งวาดการ์ดอยู่ที่โต๊ะ โคมไฟเป็นส่วนหนึ่งของสถานที่และการกระทำ
- กลางเรื่อง: โฟกัสมือที่ลบแล้วเขียนคำอวยพรใหม่ โดยมีโคมไฟจริงจาก reference อยู่ในฉาก ไม่พากย์อ่านคุณสมบัติ
- ปิดเรื่อง: พ่อส่งการ์ดให้ “วาดไม่สวย แต่ตั้งใจนะ” ลูกยิ้ม เรื่องเฉลยจาก hook เดิม
- CTA สั้นหลังจบ: “ใครชอบโคมไฟแบบในเรื่อง ดูที่ตะกร้าได้เลย”

ตัวอย่างนี้แสดงโครงเรื่อง ไม่ใช่การอ้างสรรพคุณของสินค้าจริง และไม่ใช่บทที่ผ่านการตรวจความยาวเสียงแล้ว

## ตรวจรับ

- automated: version1/legacy ไม่เปลี่ยน, UI radio เลือกได้หนึ่ง, direct/batch/queue freeze, pause/resume, API/native, subtitle preservation, no CTA duplication และ ChatGPT/Gemini JSON repair
- prompt fixtures: opening ไม่มีชื่อสินค้า/คำขาย, มีเหตุเชื่อมสินค้า, ฉากที่ไม่มีสินค้ามีสิทธิ์ไม่โชว์, CTA อยู่ตอนจบอย่างเดียว และ action ไม่ถูกอ่านเป็นบทพูด
- subjective review: hook น่าติดตาม, เรื่องมีเหตุและผล, สินค้าไม่ฝืน, ตัวละครไม่อ่านโฆษณา, จบเรื่องแล้วค่อย CTA — การทดสอบโค้ดผ่านไม่ยืนยันความเป็นธรรมชาติ
- หลัง implementation ให้ตรวจบทตัวอย่างก่อนสร้างวิดีโอ ใช้ตัวอย่างสินค้าหลากหมวดด้วย fixtures ก่อน; การสร้างคลิปจริงต้องมีขอบเขต/จำนวนที่ผู้ใช้อนุญาต ไม่เปิดหลายงานหรือวนทดลองไม่จำกัด
