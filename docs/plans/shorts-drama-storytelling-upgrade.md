# แผนรวมรูปแบบการเล่า Story Shorts + ละครสั้น AI

วันที่: 2026-09-21
สถานะ: ลงมือแกนหลักระยะ1–2 และโหมดภาพล้วนแล้วใน candidate0.15.397; full2020 testsผ่าน พร้อมชุด Extension397 ยังไม่ใช่ installed E2E pass ดู docs/reports/storytelling-397/README.md ของเสริมระยะ3 ตามข้อ7 ยังแยกทำภายหลัง

## 1. เป้าหมายและขอบเขต

นำแผนรูปแบบการเล่าของ Shorts มาใช้กับละครสั้นด้วย โดยเฉพาะตัวละครพูดและแสดงเอง ไม่มีผู้บรรยายภายนอก ไม่ใช่นำบทบรรยายไปให้ตัวละครขยับปากอ่าน พร้อมลดความซับซ้อนของหน้าละครและรักษาการทำงานหลาย EP

ใช้ Story engine, Series manager, คิวกลาง, checkpoint และ Extension เดิม ไม่สร้างระบบส่งงานใหม่ซ้ำ ไม่รวมการแก้ Shopee posting, login, server หรือการ retry ของเว็บเข้าในงานนี้

รอบวิเคราะห์ใช้ smartflow-operator ตรวจ source และสถานะอ่านอย่างเดียว: bridge ต้องการ Extension 0.15.396, Product/Story/Presenter ไม่ active, คิวพักอยู่ ณ เวลาตรวจ ไม่ได้เปิด/ปิดโปรแกรมหรือทดลองสร้างสื่อ และไม่ได้รันชุดทดสอบในรอบวางแผนนี้

## 2. สิ่งที่มีอยู่แล้วและต้องรักษา

- Shorts มี actor_dialogue รุ่น 2 สำหรับสนทนาไม่มีผู้บรรยาย ใช้เสียงวิดีโอและปิดซับ แต่ยังไม่มีโหมดผู้พูดคนเดียวโดยเฉพาะ
- ละครมี Character Bible, plot_board, สรุปเหตุการณ์ จุดค้าง ภาพอ้างอิงจาก EP ก่อน และปกประจำซีรีส์แล้ว
- ละครสร้าง EP ทีละตอน โดยอ่านผลตอนก่อนตอนเริ่มงาน ไม่สร้างทุก Job ล่วงหน้า
- มีเสียงพากย์แยกตัวละครผ่าน API, บทพูดรายฉาก, ตรวจไฟล์ภาพ และ Storyboard อยู่แล้ว
- มีคิวที่เลือกทำเฉพาะซีรีส์, ทำต่อจาก checkpoint, เพิ่ม EP หลังจบ และการกันผลเก่ามาทับงานใหม่แล้ว ต้องต่อยอด ไม่เขียนทับทั้งระบบ
- ตัวเลือกเสียงหลักชุดใหม่ซ่อน checkbox ซับเก่าไว้แล้ว ไม่ถือว่าทุก input ใน HTML เป็นตัวเลือกที่ผู้ใช้ยังมองเห็น

## 3. ข้อค้นพบจาก source

| จุดตรวจ | หลักฐาน/ความหมาย | แนวทางในแผน |

| ข้อมูลจำเป็นซ่อน แต่ปุ่มเริ่มตรวจไม่ครบ | ตัวละครอยู่ใน details ที่ปิด; UI เปิดปุ่มสร้างตามชื่อเรื่อง แต่ backend ต้องมีอย่างน้อยหนึ่งตัวละคร | เปิดการ์ดตัวละครที่จำเป็นอัตโนมัติ พร้อมเตือนตรงช่องและพา focus ไปยังข้อมูลที่ขาด |
| เสียงตัวละครกับเสียงจากคลิปชวนสับสน | ช่อง voice_reference_id อยู่ในการ์ดตัวละคร แต่เสียงต้นฉบับไม่ใช้ TTS reference นี้; Presenter เป็นภาพซ้อนแบบเงียบ ไม่ใช่นักแสดงพูดในฉาก | แสดงช่องเสียง API เฉพาะโหมดที่ใช้จริง อธิบายเสียงจากคลิป และแยกภาพซ้อนออกจาก cast |
| พล็อตตั้งต้นเป็นโครงทั่วไป | renderDramaPlotBoard และ _normalize_plot_board เติมข้อความเปิดเรื่อง/ขยายปม/คลี่คลาย ไม่ใช่ AI วางพล็อตเฉพาะเรื่องครบแล้ว | เรียกว่าโครงร่างเริ่มต้น; เสนอปุ่ม AI ช่วยวางพล็อตเป็นขั้นเสริมที่ผู้ใช้กด ไม่เรียก AI เมื่อเปลี่ยนตัวเลือก |
| คะแนนความต่อเนื่องไม่ใช่การยืนยันใบหน้า | DramaContinuityValidator ตรวจการเปิดไฟล์/ขนาด/แนวภาพ การเอ่ยชื่อ และหัวข้อร่วมของ visual_bible; UI แสดงเป็นตรวจความต่อเนื่อง XX% ผ่าน | เปลี่ยนชื่อเป็นตรวจข้อมูลอ้างอิง/ไฟล์ แยกจากตรวจภาพและเสียงจริง เพิ่มภาพเทียบ EP ก่อน/ปัจจุบัน ไม่อ้างล็อกใบหน้า 100% |
| ข้อความปลายตอนมีโอกาสขัดกัน | episode_context มีข้อความท้ายให้ชวนติดตาม EP ถัดไปทั่วไป ขณะที่ _write_drama_request แยกตอนสุดท้ายต้องปิดเรื่อง | สร้าง ending_rule จากแหล่งเดียวตาม final/open_ended/ค่าที่ผู้ใช้เลือก |
| สรุปจำนวนฉากอ่าน control ผิดชนิด | creator_ux.js ใช้ selectedOptions กับ drama-scenes ที่เป็น range จึงไม่ได้ค่าตัวเลขสำหรับสรุป | อ่าน value ของ range และแสดงจำนวน EP/ฉากให้ถูกต้องในสรุปก่อนสร้าง |

ข้อจำกัดจากโค้ดอีกจุดที่ควรเพิ่ม regression: DramaSeriesManager.create กรอง cleaned_characters แล้ว zip กลับกับรายการ raw เดิมสำหรับคัดลอกรูป หากรายการแรกว่างและรายการถัดไปมีข้อมูล อาจผูกรูปผิดตำแหน่งได้ ปัจจุบัน Hybrid กรองแถวว่างก่อนส่งอยู่แล้ว จึงยังไม่ใช่บั๊กที่ยืนยันว่าเกิดผ่านฟอร์มนี้ แต่ควรผูกด้วย ID/source ที่ผ่านตรวจแล้วก่อนเพิ่มการ์ดตัวละครแบบย้ายลำดับ

ทั้งหมดเป็นข้อค้นพบจากโค้ด/ข้อจำกัดของ UX ไม่ใช่ผลทดสอบคุณภาพคลิปละครจริงในรอบนี้

## 4. รูปแบบการเล่าร่วมกัน

เลือกได้ครั้งละหนึ่งโหมดด้วยการ์ด radio กะทัดรัด ไม่ทำเป็นสวิตช์หลายอันที่เปิดขัดกันได้

| โหมด | ลักษณะบท | การใช้กับละคร |
| --- | --- | --- |
| ผู้บรรยายเล่าเรื่อง | เล่าเหตุการณ์ให้คนดูฟัง รองรับทางเดิม | รักษาพฤติกรรมซีรีส์เก่า; งานใหม่แสดงชัดว่าอาจมีบทตัวละครประกอบ |
| ตัวละครพูดเอง | ผู้พูดหลักคนเดียว อยู่ในเหตุการณ์ พูดกับตัวเองหรือกล้องตามที่เลือก ไม่มีเสียงเล่านอกเรื่อง | ละครมุมมองบุคคลเดียว มีตัวประกอบไม่พูดได้ ไม่บังคับเพิ่มผู้พูดที่สอง |
| ตัวละครสนทนา | บทโต้ตอบ มีผู้ฟัง จังหวะเว้นและปฏิกิริยา ไม่มีผู้บรรยาย | ตัวเลือกแนะนำสำหรับละครใหม่; มีอย่างน้อยสองผู้พูดในตอน แต่ไม่ต้องพูดทุกฉาก |
| เล่าเรื่องด้วยภาพ | การกระทำ สีหน้า เสียงแวดล้อม/เพลง ไม่มีบทพูด | ละครเงียบหรือคลิปเล่าด้วยภาพ; ทำระยะถัดไป เพราะตัวตรวจเดิมยังบังคับบทพูดที่ไม่ว่าง |

แยกคำว่า “ผู้บรรยาย”, “คำบรรยายบนจอ” และ “ภาพตัวละครซ้อนวิดีโอ” ออกจากกัน การไม่มีผู้บรรยายไม่ใช่การปิดซับอย่างเดียว

โหมดตัวละครใหม่ตั้งต้นปิดซับตามความต้องการเดิม แต่เสนอให้เปิดซับแยกได้ภายหลังโดยถอดจากเสียงจริง ไม่เอาคำบรรยายฉากมาแสดงเป็นบทพูด การเปิดซับจากเสียงจริงอาจใช้ API ต้องบอกก่อน ไม่เปลี่ยนพฤติกรรมงาน actor รุ่น 2 ที่บันทึกแล้ว

โทนเรื่องเลือกได้หนึ่งค่า: อัตโนมัติ / ตลก / อบอุ่น / ดราม่า / ลึกลับ ส่วน hook, ตอนจบ, ความกระชับ และ CTA อยู่ใน “ปรับแต่งบท” ไม่เพิ่มเมนูซ้ายใหม่ ไม่ยกกฎขายสินค้าของ product_short_film_ad มาใช้กับละครทั่วไป

## 5. ระบบบทและเสียงที่เสนอ

1. เพิ่ม storytelling_options แบบมี version: mode, tone, hook, ending, cta_enabled และค่าขั้นสูงที่ตกลงไว้ แยกออกจาก visual_style, audio_choices และ provider
2. บันทึกค่าจากฟอร์มครั้งเดียวต่อคำสั่ง สืบทอดใน series → EP → job → queue → AI request → motion request → composition; คิว/ทำต่อ/เปิดใหม่/เพิ่มตอนต้องไม่อ่านค่าใหม่จากฟอร์มมาทับ
3. แยกข้อมูลแต่ละฉากเป็นเหตุการณ์ที่มองเห็น ผู้พูด ผู้ฟัง คำพูด อารมณ์/วิธีแสดง จังหวะพัก และเวลา ห้ามนำคำบรรยายการกระทำหรือชื่อผู้พูดไปอ่านออกเสียง
4. บทสนทนาควรมีเป้าหมายของตัวละคร สิ่งกระตุ้นให้ตอบ และการเปลี่ยนแปลงหลังสนทนา ไม่ใช่เล่าเรื่องบุคคลที่สามด้วยปากตัวละคร การตรวจโครงสร้างช่วยได้ แต่ความเป็นธรรมชาติต้องฟัง/ดูผลจริง
5. ตรวจรายชื่อ/ID กับ cast และตัวละครที่อยู่ในฉาก ใช้รายการเดิมข้าม EP ไม่อนุญาตให้ AI ส่ง Character Bible ใหม่แล้วทับ cast ทั้งชุดโดยอัตโนมัติ
6. โหมดตัวละครแสดงเองระยะแรกใช้เสียงจาก Google Flow สำหรับ Drama; Story รักษาความเข้ากันได้กับ Google Flow/Meta ตามที่รองรับเดิม Drama ปัจจุบันยังไม่มี Meta ในตัวเลือก จึงไม่เพิ่ม Meta แฝงในงานนี้
7. ไม่เปลี่ยน provider หรืออนุมัติค่าใช้จ่ายเอง เมื่อวิธีสร้างวิดีโอเดิมไม่รองรับการพูดในฉาก ให้แสดงเหตุผลและให้ผู้ใช้เลือกก่อนส่งงาน ภาพเคลื่อนไหวในเครื่อง + TTS ต้องไม่ถูกเรียกว่าลิปซิงก์จากนักแสดง
8. ซ่อนเสียง API รายตัวเมื่อใช้เสียงคลิป; native voice อาจเปลี่ยนบุคลิกเสียงข้ามฉาก/EP แม้ใช้คำอธิบายเดียวกัน ต้องแสดงข้อจำกัดจริง ยังไม่อ้างล็อกเสียงจากรายการ SmartSub ได้ใน Flow
9. รักษา API TTS legacy ที่บังคับ Normal/1.0x อารมณ์ในบทใหม่ใช้เป็นทิศทางการแสดง ไม่เปลี่ยนพารามิเตอร์เสียง API ที่มีข้อกำหนดเดิม
10. เวลาบทต้องอิง duration ที่เลือก/รองรับจริง เผื่อผู้ฟังตอบสนองและกล้อง ไม่บีบทุกคำเข้า 8 วินาทีหรือปรับความเร็วเสียงอัตโนมัติ ฉากเงียบต้องเป็นสถานะที่อนุญาต ไม่ถูก fallback เป็นบรรยาย
11. โหมดไม่มีผู้บรรยายห้าม fallback ผู้พูดที่ไม่รู้จักเป็นผู้บรรยาย ห้ามเติม CTA ใน result normalization, repair prompt หรือ final composition เมื่อปิดไว้
12. ปัญหาบทต้องแยกจากปัญหาส่งเว็บ คงกติกา receipt/unknown Send และ recovery เดิม ไม่เพิ่มการส่งซ้ำไม่จำกัดเพื่อแก้คุณภาพบท

## 6. UX/UI ละครสั้นใหม่

หน้าเดิมแบ่งเป็นสามส่วน ไม่สร้าง wizard บังคับคลิกหลายหน้าหรือคิวซ้ำ

### เรื่องและรูปแบบ

- ชื่อเรื่อง + โครงเรื่องสั้น + รูปแบบการเล่า + โทน
- มีตัวอย่างบทสั้นของโหมดที่เลือกให้เข้าใจต่างกันอย่างไร ไม่เรียก AI เพื่อแค่พรีวิวการเลือก
- ตัวเลือกบทเพิ่มเติมพับไว้; ผู้บรรยาย/CTA/ซับไม่แสดงชื่อกำกวม

### ตัวละครและตอน

- การ์ดตัวละครหลักแสดงให้เห็น; “เพิ่มตัวละคร” แทนฟอร์มว่างหลายใบ รองรับขอบเขตเดิมของ Drama สูงสุด 4 คนพร้อม ID คงที่
- รูป/ชื่อ/บุคลิกย่อ ส่วนรายละเอียดและเสียงอยู่ในส่วนขยายตามโหมด แสดงข้อมูลจำเป็นที่ยังขาดทันที
- จำนวน EP และฉาก พร้อมสรุปความยาวประมาณจากค่าจริง ไม่สัญญาเวลาเสร็จหรือเครดิตที่ไม่ทราบ
- โครงพล็อตย่อราย EP; ปุ่มตรวจบท/Storyboard เดิมเข้าถึงจากตอนที่เลือก ไม่บังคับเลือก Job ซ้ำหลายจุด

### สร้างและติดตาม

- ปุ่มหลัก “สร้างตอนนี้” และปุ่มรอง “เพิ่มลงคิว” ใช้เส้นทางเดิม มีสรุปโหมด/เสียง/ซับ/จำนวนตอนก่อนสร้าง
- หน้า Drama แสดงรายชื่อซีรีส์และความคืบหน้าแบบย่อ คิวเต็มและการจัดลำดับอยู่หน้า “คิวสร้างคลิป” จุดเดียว ไม่ลบ manifest หรือข้อมูลคิว
- จัดการเฉพาะซีรีส์ต้องชัด ไม่ให้ปุ่มพัก/ทำต่อที่ดูเหมือนเฉพาะซีรีส์ไปควบคุมทุกงานโดยไม่บอก
- รวมปุ่มรองในเมนู “จัดการ”; แยก “ทำต่อจากที่หยุด”, “เพิ่ม EP ใหม่”, “สร้างใหม่” ให้ต่างกัน ห้ามล้างตอนสำเร็จเพราะกดทำต่อ
- Progress บอก EP/ฉาก/ขั้นตอนจริง เช่น “EP 2/4 • ฉาก 3/8 • รอวิดีโอ”; เวลาอัปเดตล่าสุดช่วยอธิบายช่วงรอ แต่ไม่ใช้เวลาผ่านไปอย่างเดียวตัดสินว่างานล่ม
- ใช้สไตล์สวิตช์แบบ 1 ที่ผู้ใช้เลือกไว้, ไอคอนชุดเดิม, motion เบา ๆ, reduced-motion, focus/keyboard และหน้าจอแคบ ไม่ออกแบบระบบหน้าตาใหม่ซ้อนอีกชุด
- ตรวจข้อความเก่าเกี่ยวกับ Flow fallback, ปิด Chrome และ “ล็อกใบหน้า” ให้ตรงความสามารถปัจจุบัน ไม่เปลี่ยน automation เพื่อให้เข้ากับข้อความเก่า

## 7. สิ่งเสริมเฉพาะละครหลังแกนหลักนิ่ง

- AI ช่วยวางพล็อตทั้งซีรีส์ก่อนสร้างภาพ: เป็นปุ่มเสริมที่เรียกผ่าน provider ที่ผู้ใช้เลือกและบันทึกคำตอบไว้ ผู้ใช้ตรวจ/แก้ได้ ไม่บังคับขั้นเพิ่มสำหรับคนใช้ one-click
- ความทรงจำรายตัวละคร: สิ่งที่รู้/ยังไม่รู้ ความสัมพันธ์ เป้าหมาย และปมที่คลี่คลายแล้ว เพื่อลดตัวละครรู้ข้อมูลก่อนเหตุการณ์เกิด
- เปรียบเทียบภาพตัวละครต้นฉบับ/ตอนก่อน/ตอนนี้ พร้อมฟังเสียงตัวอย่าง และแยกสถานะตรวจข้อมูลออกจากตรวจคุณภาพจริง
- การปรับพล็อตหลังเริ่มซีรีส์ใช้ revision เฉพาะ EP ที่ยังไม่ส่ง; ถ้าแก้ตอนก่อนที่มีตอนหลังสร้างแล้ว ให้แสดงรายการผลกระทบ ไม่สร้างใหม่ทั้งชุดเอง
- โหมดเงียบเต็มเรื่อง และเลือก cast จากคลังเดิม: เชื่อมกับ docs/plans/shorts-motion-graphics-cast.md โดยไม่ถือว่าทั้งแผนคลัง/โมชั่นกราฟิกได้รับอนุมัติให้ทำพร้อมกันแล้ว

## 8. ลำดับลงมือและเกณฑ์ทดสอบ

### ระยะ 1 — แกนบท/เสียงร่วมและข้อขัดแย้ง

- เพิ่ม options มี version และ mapping งานเก่า; รวม prompt sections และ CTA/ending จากแหล่งเดียว
- ต่อยอดสนทนา + เพิ่มผู้พูดคนเดียวสำหรับ Shorts และ Drama; เก็บซีรีส์เดิมเหมือนเดิม
- ผูกสัญญาตลอดเส้นทาง รวม Extension validation และการซ่อมคำตอบ ChatGPT/Gemini
- ตรวจด้วย fixture ว่าไม่มีบรรยาย/CTA หลุด ไม่มีการอ่าน action และไม่มีเสียง API ทับ native

### ระยะ 2 — หน้าใช้งานและความน่าเชื่อถือของสถานะ

- ปรับสามส่วนด้านบน, ตัวละคร, สรุปค่าจริง, เงื่อนไขปุ่ม, คิว/ปุ่มจัดการและข้อความคะแนนความต่อเนื่อง
- เพิ่มชุดทดสอบกรอกชื่ออย่างเดียว, ตัวละครว่าง/ลำดับเปลี่ยน, speaker ผิดคน, duplicate ID และค่า provider/เสียงที่ไม่รองรับ
- ทดสอบ enqueue, double-click, เปลี่ยนฟอร์มระหว่าง await, ปิดเปิดใหม่, หยุดแล้วทำต่อ, เพิ่ม EP, ผลล่าช้าจาก attempt เก่า โดยใช้ข้อมูลจำลอง ไม่แตะคิวผู้ใช้

### ระยะ 3 — คุณภาพเรื่องและฟังก์ชันเสริม

- โหมดภาพล้วน, โครงพล็อตเฉพาะเรื่อง, ความทรงจำตัวละคร และพรีวิวต่อเนื่องตามลำดับความสำคัญ
- ทดสอบ silent scene/เรื่องเงียบไม่ถูกปฏิเสธเพราะ narration ว่าง และไม่ถูกเติมเสียงเอง

### ก่อนส่งมอบเมื่อได้คำสั่งลงมือ

- focused tests แล้ว full suiteหนึ่งรอบหลังโค้ดนิ่ง ตรวจ source จริงทั้ง UI/controller/queue/desktop/Extension; source Extension เปลี่ยนต้องเพิ่มรุ่นและจับคู่ desktop ตามกฎโครงการ
- UI smoke ผ่าน EXE ปกติเมื่อปลอดภัย ตรวจคีย์บอร์ด ฟอร์มแคบ ภาพเทียบ สรุปโหมด และพัก/ทำต่อเฉพาะซีรีส์
- provider E2E ต้องขอบเขตชัดและผู้ใช้อนุญาตก่อนใช้เครดิต เสนอเริ่มคลิปผู้พูดเดี่ยวสั้นหนึ่งงาน กับละครสอง EP เพื่อทดสอบ continuity แต่ยังไม่เริ่มและไม่เพิ่มจำนวนทดสอบเอง
- ทดสอบ ChatGPT/Gemini และทุกโมเดลที่อยู่ในเมนูตามขอบเขตความเข้ากันได้ ไม่อ้าง mock เป็น installed pass; แยกรายการที่ยังไม่ได้ทดสอบจริง
- ฟัง/ดูคลิปจริง: ผู้พูดถูกคน ผู้ฟังตอบสนอง บทไม่เป็นบรรยาย ปาก/เสียง/เวลาสอดคล้อง EP ต่อเรื่อง และไม่มีเสียงซ้อน ผล JSON ผ่านอย่างเดียวไม่รับรองคุณภาพการแสดง
- คงคลิป ภาพ เสียง receipt และงานเก่า ไม่เริ่มใหม่อัตโนมัติเมื่อผลส่งเว็บยังไม่แน่นอน ไม่รีสตาร์ตงานผู้ใช้เพื่อทดสอบ
