# แผนแก้ฟังก์ชันทับซ้อน SmartFlow AI

วันที่ 27 กันยายน 2026 • แผนได้รับอนุมัติและลงมือครบแล้ว ผลการแก้/ขอบเขตทดสอบอยู่ที่ `docs/reports/function-overlap-fixes-20260927.md` • ไม่เปลี่ยนรุ่น Extension และไม่บิลด์ตัวติดตั้ง

## 1. หลักฐานและขอบเขต

อ้างอิง `docs/reports/function-overlap-audit-20260927.md` ซึ่งยืนยัน 9 กลุ่มปัญหาจากซอร์สจริงและการจำลองด้วยโค้ดจริง ไม่ใช่การคาดเดาจากหน้าตาอย่างเดียว ฐานตรวจคือซอร์ส 0.15.455; ผลทดสอบรุ่นนั้นก่อนการตรวจครั้งนี้ไม่ได้แปลว่า 9 ปัญหาใหม่ถูกแก้แล้ว

เป้าหมายคือทำให้สิ่งที่ผู้ใช้เลือก สิ่งที่โปรแกรมบันทึก และสิ่งที่ Extension/ตัวประกอบวิดีโอทำ ตรงกัน โดยแก้เฉพาะเส้นทางที่พิสูจน์ว่าผิด ไม่เขียนระบบออโตเมชันใหม่ทั้งหมด

กติกาที่ต้องรักษา:

- งานเก่า รูป เสียง คลิป Final ประวัติ และใบรับผลคำขออยู่ครบ ไม่แปลงงานที่กำลังทำตามค่าฟอร์มใหม่
- ค่าเริ่มต้นใช้กับแบบฟอร์มใหม่เท่านั้น เมื่อผู้ใช้แก้แบบฟอร์มแล้ว การโหลดสถานะซ้ำต้องไม่ทับการเลือกนั้น
- การแก้งาน/รายการคิวอ่านค่าจากงานนั้น ไม่อ่านจากฟอร์มสร้างใหม่หรือค่ากลางแทน
- การแก้เฉพาะช่องต้องไม่เท่ากับดึงค่าปัจจุบันมาแทนทุกช่อง ไม่เพิ่มการรีเซ็ตโดยปริยาย
- ไม่เปลี่ยนผู้ให้บริการหรือโมเดลที่ผู้ใช้บันทึกไว้เอง ไม่เริ่มสร้าง/โพสต์เพื่อทดสอบโดยไม่ได้รับอนุญาต
- ไม่แตะกติกา Send, Stop, การรอภาพ, เจ้าของคำขอ และ recovery ที่ไม่เกี่ยวข้องกับ 9 จุดนี้
- รอบลงมือทำในอนาคตแก้โปรเจกต์หลักกับ Extension หลักก่อน ไม่สร้างตัวติดตั้งหรือเปิดใช้รุ่นใหม่อัตโนมัติ

## 3. รายละเอียดครบ 9 จุด

### A1. เครื่องมือซ่อมสินค้าแบบเดิมต้องใช้ค่าของงานที่เลือก

**ยืนยันแล้ว:** ปุ่มซ่อมเก่าอ่าน AI/โมเดลจากฟอร์มสร้างสินค้าใหม่ และ `multi_flow` บังคับ Flow แม้งานเป็น Meta เส้นทางทำต่อปกติไม่ใช่จุดที่พบข้อผิดพลาดนี้

**แก้ที่:** `web_ui/app.js`, `ui/main_window.py` เฉพาะคำสั่งเครื่องมือสินค้าเดิม

- อ่าน AI, โมเดล และผู้สร้างวิดีโอจาก snapshot ของงานที่เลือก
- หากต้องเปลี่ยนผู้ให้บริการ ให้ผ่านตัวเลือกเฉพาะงานที่ผู้ใช้ยืนยันแล้วเท่านั้น
- คำสั่งเฉพาะ Flow ต้องไม่แสดงเป็นคำสั่งทั่วไปสำหรับ Meta; ใช้เส้นทางที่รองรับอยู่จริง หรือปิดปุ่มพร้อมบอกเหตุผล
- งานเก่าที่ไม่มีฟิลด์บางตัวใช้กติกา compatibility ที่ตรวจสอบได้ ไม่หยิบค่าฟอร์มปัจจุบันมาเติมโดยเงียบ

**ผ่านเมื่อ:** เปิดงาน ChatGPT/Meta แล้วเปลี่ยนฟอร์มสร้างใหม่เป็น Gemini/Flow ก่อนกดเครื่องมือ งานเดิมยังใช้ค่าของตัวเอง; รูป/คลิปที่เสร็จแล้วและคำขอเดิมไม่ถูกเปลี่ยน

### A2. แก้ชื่อรายการคิวต้องไม่ล้างข้อความปกเดิม

**ยืนยันแล้ว:** ตัวอ่านค่าปกส่ง `headline:''` เสมอ แม้โหลดข้อความเดิมมาแล้ว ทำให้ backend บันทึกทับเมื่อแก้เฉพาะชื่อ

**แก้ที่:** `web_ui/ai_cover.js`, `ui/creation_queue.py`; ตรวจ compatibility กับ `core/ai_cover.py` และ `browser_extension/chatgpt.js`

- การแก้รายการเดิมต้องเก็บ headline ที่โหลดมาหากผู้ใช้ไม่ได้แก้ข้อความปก
- แยก “ไม่แก้ช่องนี้” ออกจาก “ผู้ใช้ขอล้างช่องนี้” ในข้อมูลที่ส่งแก้ไข
- แบบฟอร์มงานใหม่ยังใช้ข้อความปกอัตโนมัติได้ ไม่เพิ่มช่องใหม่ที่ไม่จำเป็น
- ไม่แก้ภาพปก/Final ที่สร้างสำเร็จแล้ว

**ผ่านเมื่อ:** เปลี่ยนชื่อคิวอย่างเดียวแล้ว headline, scene index และค่าปกอื่นเท่าเดิม ทั้งรายการเก่าที่มีข้อความกำหนดเองและรายการใหม่แบบอัตโนมัติ

### A3. แยก Dry Run เก่าออกจากออโตโพสต์ Shopee ใหม่

**ยืนยันแล้ว:** Dry Run/ยืนยันก่อนโพสต์ของระบบเดิมไม่ควบคุม service โพสต์ใหม่ แต่ระบบใหม่ยังมีคำยืนยัน “โพสต์จริง” ของตัวเอง ไม่ได้พบการโพสต์ข้ามการยืนยัน

**แก้ที่:** `web_ui/index.html`, `web_ui/app.js`, `web_ui/shopee_posting.js`; ตรวจข้อความสถานะและเส้นทาง `queue_safety` ใน `ui/main_window.py`

- เอาตัวเลือกความปลอดภัยของระบบเก่าออกจากบริเวณควบคุมออโตโพสต์ใหม่ หรือแยกไว้กับเครื่องมือเดิมและติดชื่อขอบเขตชัดเจน
- คงการยืนยันโพสต์จริงของ service ใหม่ และไม่ใช้ข้อความ “โหมดทดสอบ” ที่ไม่ครอบคลุมปุ่มนั้น
- ไม่ลบเครื่องมือเชื่อมต่อโทรศัพท์/ADB ที่ยังใช้ และไม่เพิ่มระบบจำลองโพสต์ใหม่โดยปริยาย

**ผ่านเมื่อ:** ไม่มีตัวเลือกที่ทำให้เข้าใจว่าเปิด Dry Run แล้วปุ่มใหม่จะไม่โพสต์; ยกเลิกคำยืนยันแล้วไม่มีคำสั่งเริ่มโพสต์; ยืนยันแล้วตัวรับจำลองได้คำสั่งจริงเพียงครั้งเดียว ทดสอบโดยไม่โพสต์ขึ้นบัญชี

### B1. วิธีเล่าเรื่องเป็นตัวควบคุมหลักเพียงชุดเดียว

**ยืนยันแล้ว:** การซ่อนปุ่มสนทนาเก่าอาศัยตำแหน่งติดกับช่อง provider เมื่อโมดูลอื่นแทรก UI จึงซ่อนไม่สำเร็จ และปุ่มเก่าเปลี่ยนเสียง/ซับขัดกับรูปแบบการเล่าใหม่

**แก้ที่:** `web_ui/storytelling.js`, `web_ui/media_audio.js`; ตรวจทุกฟอร์มที่ใช้ร่วมกัน

- เอาสวิตช์ legacy ออกจากฟอร์มที่มีตัวเลือกรูปแบบการเล่าใหม่ โดยอ้างอิง control โดยตรง ไม่ใช้ตำแหน่งข้างเคียง
- ให้รูปแบบผู้บรรยาย/พูดเดี่ยว/สนทนา/ภาพเล่าเรื่อง เป็นเจ้าของการเลือกบทบาทเพียงจุดเดียว แสดงเฉพาะโหมดที่หน้านั้นรองรับอยู่แล้ว
- ตัวเลือกเสียงแสดงเฉพาะชุดที่ใช้ได้กับรูปแบบนั้น ไม่มี radio ที่ถูกเลือกแต่ถูกปิดใช้งาน
- คงการอ่านค่ารุ่นเก่าของ backend ไม่ลบ `actor_dialogue` ออกจากงานเก่าแบบเหมารวม และไม่บังคับปิดซับของงานรุ่นใหม่ตามกติกา legacy

**ผ่านเมื่อ:** โหลดสคริปต์ทั้งหมดตามลำดับจริงแล้วไม่เห็นสวิตช์ซ้ำ; สลับรูปแบบไปกลับใน Shorts/หลายคลิป/Drama ไม่ได้ค่าบทกับเสียงขัดกัน; งานเก่าทำต่อด้วยค่าเดิม

### B2. ค่าซับตั้งต้นต้องตรงทุกฟอร์มใหม่

**ยืนยันแล้ว:** โหลดค่าหลักลง checkbox เก่าที่ซ่อนอยู่ แต่ชุดเสียงใหม่คัดลอกค่าก่อนโหลดเสร็จ จึงแสดงและส่ง true แม้ค่าหลักเป็น false

**แก้ที่:** `web_ui/app.js::hydrateForms`, `web_ui/media_audio.js` และจุดสร้างฟอร์ม

- เมื่อค่าตั้งต้นพร้อม ให้ตั้งค่าตัวควบคุมปัจจุบันครั้งแรกอย่างชัดเจน
- บันทึกว่าผู้ใช้แก้แต่ละฟอร์มแล้วหรือยัง เพื่อไม่ให้การอัปเดตสถานะ/ค่าหลักทับแบบร่างระหว่างกรอก
- ค่าของรายการคิว/งานเดิมมาก่อนค่าตั้งต้นเสมอ ลดตัวเขียนค่าซ้ำลงโดยรักษา adapter ที่จำเป็น

**ผ่านเมื่อ:** ค่าหลัก true/false ตรงช่องและ payload ของสินค้า, Shorts, Drama, คลิปยาว; ค่าโหลดช้าไม่ทับสิ่งที่ผู้ใช้เพิ่งกด; แก้ค่าหลักไม่เปลี่ยนคิวหรืองานที่บันทึกแล้ว

### B3. กรีนสกรีนในหน้าต่างแก้คิวต้องอ่านและบันทึกรายการนั้น

**ยืนยันแล้ว:** หน้าต่างแก้คิวแสดงค่ากลาง Product แต่ backend ไม่รับการแก้ green ในโหมดแก้ธรรมดา จึงเปลี่ยนแล้วไม่มีผล

**แก้ที่:** `web_ui/green_screen.js`, `web_ui/creation_queue.js`, `ui/creation_queue.py`

- โหลดค่าจากรายการคิวที่กำลังแก้ ไม่โหลดจากแบบฟอร์มอื่น
- เพิ่มการบันทึก green เฉพาะช่องที่รองรับในรายการที่แก้ได้ โดยไม่เปิด “ดึงค่าปัจจุบันทั้งชุด” ให้เอง
- แถวที่เริ่มทำ/ถูกล็อกหรือไม่รองรับให้แสดงอ่านอย่างเดียวพร้อมเหตุผล ไม่แสดงว่าแก้แล้วบันทึกได้

**ผ่านเมื่อ:** เปิดสองแถวที่ตั้ง green ต่างกันแล้วเห็นค่าถูกแถว; เปลี่ยน green แล้วบันทึกได้เฉพาะแถวนั้น; ชื่อ, AI, เสียง, ปก และตัวเลือกอื่นไม่เปลี่ยนตามค่ากลาง

### C1. สองทางเพิ่มคลิปยาวลงคิวต้องใช้เจตนาพักคิวเหมือนกัน

**ยืนยันแล้ว:** กดสร้างหลักส่ง `queue_only=true` เมื่อเลือกเก็บไว้ก่อน แต่ปุ่มเพิ่มลงคิวอีกทางไม่ส่งค่าเดียวกัน

**แก้ที่:** `web_ui/app.js::submitLongVideo`, `web_ui/queue_choice.js`, `web_ui/usability.js`; ตรวจ backend ที่รับ `enqueue_long_video`

- ใช้กติกาเดียวในการอ่าน checkbox และส่ง queue policy ไม่ว่ามาจากปุ่มใด
- เลือกเก็บเข้าคิวไว้ก่อนต้องไม่เริ่มรายการใหม่หลังงานปัจจุบันเสร็จ; ไม่หยุด/ยกเลิกงานที่กำลังสร้างทันที
- ไม่เลือกเก็บไว้ก่อนยังเพิ่มต่อคิวที่กำลังเดินได้ตามพฤติกรรมเดิม
- ข้อความหลังเพิ่มแยก “รอเริ่ม” กับ “ต่อท้ายคิวที่กำลังทำ” ให้ตรงสถานะจริง

**ผ่านเมื่อ:** ทั้งสองปุ่มให้ผลตรงกันในคิวว่าง/คิวพัก/คิวกำลังทำ ทั้งติ๊กและไม่ติ๊ก และป้องกันคลิกซ้ำสร้างรายการซ้ำโดยใช้กลไกเดิม

### D1. ละครสั้น: แก้กติกาพากย์ API ร่วมกับดนตรี AI ที่ขัดกัน

**ยืนยันแล้ว:** เปิดเก็บเสียงต้นฉบับติดตัวตรวจบทสนทนา แต่ปิดเก็บเสียงต้นฉบับติดตัวตรวจดนตรี AI ขณะที่ตัวตรวจตอนประกอบมีข้อยกเว้นสำหรับดนตรีรุ่นใหม่อยู่แล้ว

**แก้ที่:** `core/drama_options.py`, `core/storytelling.py`, `core/generated_music.py`, `core/story_performance.py` และ UI/พรอมต์ที่เกี่ยวข้องจริง

- ให้การเลือกในหน้า UI การสร้างงาน และการประกอบใช้กติกาที่สอดคล้องกันสำหรับรูปแบบนี้
- แยกเจตนาเก็บดนตรี/บรรยากาศออกจากการใช้เสียงพูดของคลิป: พากย์ API ต้องไม่สั่ง AI วิดีโอพูดบทเดียวกันอีกครั้ง
- จำกัดข้อยกเว้นตามสัญญาดนตรีที่เปิดจริงและผ่าน validation ใน snapshot ที่บันทึกไว้ ไม่เชื่อ marker จาก UI อย่างเดียว และไม่อนุญาตให้ทุกงานพากย์ผสมเสียงพูดต้นฉบับโดยไม่มีเงื่อนไข
- รักษาบทพูด ผู้พูด ลำดับฉาก และแผนฉากที่มีดนตรี ไม่สุ่มใหม่เมื่อทำต่อ
- หากสัญญาเสียง/พรอมต์ต้องเปลี่ยน ให้กำหนดรุ่นสำหรับงานใหม่และรักษา bytes/hash ของคำขอเดิม

**ผ่านเมื่อ:** ชุดตัวเลือกที่ UI อนุญาตผ่านทั้งตอนสร้างและประกอบ; พรอมต์ API+dubbing ไม่สั่งพูดซ้ำ; ทดสอบปิด/เปิดเพลง, เก็บ/ไม่เก็บเสียง, ระดับเสียงศูนย์, เพลงจากคลัง, marker ที่ไม่มีแผนดนตรีรองรับ และงานรุ่นเก่า โดยชุดที่ไม่รองรับต้องอธิบายตั้งแต่ก่อนเริ่ม

**ข้อจำกัด:** การแก้ validator และพรอมต์ไม่ได้รับประกันว่า AI จะไม่มีเสียงพูดหลุดเข้ามาใน soundtrack; ไม่อ้างว่าแยกดนตรีออกจากเสียงพูดได้โดยไม่มีระบบรองรับ ต้องแยกการตรวจสัญญาออกจากการทดสอบ provider จริง

### D2. คลิปยาว: เก็บเสียงต้นฉบับให้ตรงตัวเลือก ไม่ผูกกับการเปิดเพลง AI

**ยืนยันแล้ว:** renderer เก็บเสียงต้นฉบับร่วมพากย์เฉพาะเมื่อมี marker ดนตรี AI ทั้งที่หน้าจอรับตัวเลือก keep ได้โดยไม่มี marker

**แก้ที่:** `core/long_video_render.py` และตัวเลือกเสียง/ลายนิ้วมือ cache ที่เกี่ยวข้อง

- ทำให้ keep source audio เป็นพฤติกรรมชัดเจนสำหรับงานใหม่ ไม่ต้องเปิดเพลง AI เพื่อให้มีผล
- ใช้แนวทางเก็บเสียงต้นฉบับใน chapter โดยไม่ลด gain ซ้ำ แล้วผสมเสียงพากย์เต็มและปรับระดับต้นฉบับที่ Final ครั้งเดียว ตรวจให้คงจังหวะฉาก/ช่วงเงียบเมื่อข้ามขอบ chapter
- เปลี่ยนรุ่น/ลายนิ้วมือ cache ตามพฤติกรรมใหม่ ไม่ใช้ chapter cache ที่เกิดจากสัญญาเสียงคนละแบบ และไม่ลบ cache/Final เก่าทั้งหมด
- งานเก่าทำต่อตามสัญญาที่บันทึกไว้; หากจะเปลี่ยนเสียงของงานเดิมต้องเป็นการกระทำเฉพาะงานที่ผู้ใช้ร้องขอ

**ผ่านเมื่อ:** ไฟล์ทดสอบมีและไม่มีดนตรี AI ให้เสียงต้นฉบับตาม keep; ปิด keep แล้วเหลือเสียงพากย์ตามต้องการ; ระดับ 0/35/100 มีผล; หลายบทต่อกันไม่มีพากย์หรือ source audio ถูกผสมสองครั้ง

ใช้วิดีโอ/เสียงสังเคราะห์และไฟล์ชั่วคราวตรวจ FFmpeg จริงได้โดยไม่ใช้ AI credits ไม่อาศัยดูคำสั่งอย่างเดียว

## 4. UX หลังแก้

- รูปแบบการเล่าอยู่จุดเดียว ส่วนเสียงและซับเป็นตัวเลือกที่สัมพันธ์กัน ไม่มีกลไกเก่ามาเปลี่ยนเงียบ ๆ
- ตัวเลือกเสริมแสดงเมื่อเกี่ยวข้อง ไม่ย้ายทุกอย่างมาอยู่หน้าหลัก
- แก้คิวแสดง “ค่าของรายการนี้” ส่วนการใช้ค่าปัจจุบันทั้งชุดเป็นการเลือกอีกอย่างที่ชัดเจน
- เครื่องมือเฉพาะ provider ไม่แสดงว่าใช้ได้กับทุก provider
- ไม่รวมสิ่งที่ต่างหน้าที่กัน: คิวสร้าง/คิวโพสต์, แนวบท/วิธีเล่า, นายแบบสินค้า/ผู้บรรยายซ้อนภาพ, ปก/อินโทร และค่าตั้งต้น/ค่าเฉพาะงาน

## 5. โปรแกรมกับ Extension ต้องตรวจคู่กันอย่างไร

9 ปัญหานี้ส่วนใหญ่มีต้นเหตุที่ UI/desktop ไม่ใช่ตัวคลิกบนเบราว์เซอร์ จึงไม่แก้ตัวคลิก/การกู้คำตอบโดยไม่จำเป็น

1. ตรวจข้อมูลจริงจากฟอร์ม → คิว/งาน → package → Extension สำหรับ provider/model, storytelling/audio, subtitles, generated music และ cover headline
2. ยืนยัน Extension อ่านค่าของคำขอ/งานนั้น ไม่รับค่าหลักที่เปลี่ยนภายหลัง และยังอ่านงานเก่าได้
3. หากแก้สัญญาที่แลกเปลี่ยนหรือพรอมต์ ต้องแก้ source/tests ฝั่ง Extension ที่เกี่ยวข้องและ version/capability ให้เข้ากัน โดยไม่เปลี่ยนคำขอเก่าที่ส่งแล้ว
4. หากไม่กระทบโค้ด Extension ให้ระบุชัดว่าใช้โค้ดเดิมได้เพราะผ่านการตรวจส่วนเชื่อมต่อ ไม่เพิ่มรุ่นโดยไม่มีเหตุผล
5. การเตรียมโฟลเดอร์/ZIP รุ่นใหม่เป็นขั้นหลังซอร์สผ่านและอยู่ในขอบเขตส่งมอบที่อนุญาต ไม่เท่ากับ reload หรือติดตั้งให้ผู้ใช้ และไม่สร้าง installer อัตโนมัติ

## 6. เกณฑ์ทดสอบรวมก่อนแจ้งว่าแก้เสร็จ

- Regression ของ 9 จุดล้มเหลวก่อนแก้และผ่านหลังแก้ รวมเส้นทาง backend ไม่ใช่ตรวจข้อความในไฟล์อย่างเดียว
- UI แยกที่โหลดสคริปต์ทั้งชุดตามลำดับจริง: สินค้า, Shorts, หลายคลิป, Drama, คลิปยาว, คิว, ตั้งค่าเสียง/ซับ และหน้าโพสต์
- วงจรสำคัญ: ค่าเริ่มต้น → เปลี่ยนฟอร์ม → เพิ่มคิว → แก้เฉพาะช่อง → อ่านค่าประจำงาน → ทำต่อจำลอง
- ตัวเลือกที่แสดง ตำแหน่ง selected/disabled และ payload ต้องตรงกัน ไม่พบ control ซ้ำที่เป็นเจ้าของค่าเดียวกัน
- เปรียบเทียบ snapshot งานเก่า/คำขอเก่า/ตัวเลือกคิวก่อนและหลัง ไม่ใช้ข้อมูลลับหรือสื่อผู้ใช้เป็น fixture โดยไม่จำเป็น
- เสียงใช้ synthetic media หลายบท ตรวจผลไฟล์จริง รวมความยาว/แทร็ก/ระดับเสียง/การผสมครั้งเดียว
- รันชุดทดสอบรวมหลังแก้เฉพาะจุดครบ รายงานจำนวนผ่าน/ตก/ข้ามตามจริง แยกข้อผิดพลาดเดิมออกจาก regression ใหม่
- ไม่โพสต์ ไม่สร้างสื่อกับ AI ไม่แตะโปรไฟล์ Chrome จริง ไม่รีโหลด Extension หรือรีสตาร์ตโปรแกรมเพื่อทำ offline tests
- ทดสอบบริการจริงเมื่อมีขอบเขตที่ผู้ใช้อนุญาตเท่านั้น; offline ผ่านไม่ใช่ข้อพิสูจน์ว่า provider ทุกตัวทำงานครบ end-to-end

## 7. สิ่งส่งมอบเมื่อได้รับคำสั่งให้ลงมือ

1. ซอร์สแก้เฉพาะ 9 จุดพร้อม regression tests และปรับพิมพ์เขียวเฉพาะสัญญาที่เปลี่ยน
2. สรุปแต่ละจุด: สาเหตุ, พฤติกรรมก่อน/หลัง, การทดสอบจริง และเงื่อนไขที่ยังไม่ได้ทดสอบ
3. ระบุว่า Extension เปลี่ยนตรงไหนหรือใช้เดิมได้ พร้อมผลตรวจความเข้ากันได้
4. รายการตรวจสั้นสำหรับผู้ใช้: สลับวิธีเล่า, ตั้งซับ, แก้คิว, พักคิวคลิปยาว และตัวเลือกเสียง
5. ไม่สร้างตัวติดตั้ง ไม่เปิดใช้รุ่นใหม่ ไม่สร้างงานใหม่ และไม่เปลี่ยนงานที่ผู้ใช้มีอยู่เอง
